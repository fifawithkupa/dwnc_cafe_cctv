## 채점이 오답으로 세지 않는 것 — 이걸 어기면 좋은 규칙을 망가뜨린다

정답지는 **사람의 눈**이다. 사장님은 "지금 거기 뭐가 있나"를 적었지 우리
규칙이 무엇을 해야 하는지를 적은 게 아니다. 다음 둘은 **맞는 판단**이다.

| 등급 | 뜻 | 왜 안 고치나 |
|---|---|---|
| **가림모름** | 사람이 자리를 덮어서 모름 | 사람이 비키면 풀린다 |
| **지연** | 사용중↔빈자리 전이 중 확정 대기 | 성급히 확정하면 손님이 남의 자리로 간다 |

점수를 올리려고 확정 지연을 없애거나 가림 규칙을 푸는 방향의 수정은
**금지**다. 채점표의 `accepted` 가 이 둘을 포함한 수다.

## 고치는 순서 — 딱지마다 고치는 사람이 다르다

| 딱지 | 누가 | 무엇을 |
|---|---|---|
| **로직** | 기계 | 임계값 위에서 이미 잡고 있던 것을 규칙이 버렸다. 규칙을 고친다 |
| **상자밖** | 기계 | 물건이 자리 상자 바로 밖이다. `layouts/*.json` 상자를 다시 그린다 |
| **임계값경계** | 기계 | 전역 기본값을 내려보고 **72칸 전체 점수로 판단**. 나빠지면 되돌리고 파인튜닝으로 강등 |
| **파인튜닝** | 사람 | 모델이 못 본다. **고치지 말고 목록에 쌓는다** |

**한 번에 하나만 고친다.** 둘을 같이 고치면 어느 쪽이 점수를 올렸는지 알 수
없고, 하나가 다른 하나를 망가뜨려도 안 보인다.

## 과적합 방지 — 사진 6장에 코드를 맞추지 않기

`plan.md` §6: 4.8분짜리 영상에는 A/B 차이를 가릴 통계력이 없다.

- 수정마다 **전체 칸**을 다시 잰다. 한 칸 살리려다 두 칸 죽이면 되돌린다
- 실패 사례의 **실제 좌표로 회귀 테스트**를 추가한다 (이 저장소의 관례)
- **금지**: 자리 이름(`T4`)이나 시각(`60초`)이 들어간 규칙. 규칙은 늘
  "왜 그런가"로 설명돼야 한다
- **금지**: 임계값을 소수점 둘째자리까지 맞추기. 실측을 줄세워 **빈 구간의
  가운데**를 잡는 기존 방식을 지킨다 (`plan.md` §3)

## 언제 멈추나

**'로직'과 '상자밖'이 0개**이고 **'임계값경계'를 전부 시도했을 때.**

그때 `results/<실행>/루프결과.md` 에 남긴다:

| 칸 | 내용 |
|---|---|
| 점수 | 전체 칸 중 몇 칸, 시작 → 끝. 방향별(놓침/헛것/…) 분해 |
| 고친 것 | 무엇을 왜 고쳤고 어느 칸이 살아났나 |
| **파인튜닝 숙제** | 자리·시각·클래스·**모델이 최대 몇 %로 봤나** → 그대로 `plan.md` T11 학습 데이터 요구사항 |
| 사장님 결정 필요 | 기계 권한 밖 카드 |

보고는 **비개발자 기준**으로 쓴다 (`CLAUDE.md`): 함수명·파일명을 설명의
본문으로 쓰지 않고, 트레이드오프를 숨기지 않는다.

## 윈도우에서 걸리는 것

- 콘솔이 cp949라 한글 출력이 깨져 보인다. **파일은 UTF-8이라 멀쩡하다** —
  터미널 출력 대신 생성된 `.md` 를 읽어라
- OpenCV는 한글 경로에 `imwrite`가 조용히 실패한다 → `cv2.imencode` + `Path.write_bytes`
