# 검출 검사 하네스 — "YOLO가 이 카페를 제대로 보는가"

> 작성: 2026-09-01
> 기준 커밋: `JINOI/main` = `22519de`
> 관련: `plan.md` T14·T2, `CLAUDE.md`

## 1. 이 문서가 답하는 질문

**"지금 우리 코드가 실제 카페 영상에서 사람을 제대로 잡고 있는가?"**

`plan.md` §0-a는 2026-08-31에 "한 번도 실제 영상으로 돌려본 적이 없다"가 해소됐다고
적었지만, 그날 실제로 한 것은 `_preseed`를 **각 각도의 5초 지점 한 장**에 돌린
것뿐이다(§0-c). 즉:

- 돌아간 것: 테이블·의자 검출기, 정지 이미지 1장
- **한 번도 안 돌아간 것: 영상 전체를 훑는 판정 파이프라인**
  (시간 추적, 포즈 판정, 좌석 상태 확정)

그래서 지금 아무도 모른다 — 이 코드가 78초짜리 영상 하나를 끝까지 돌 수 있는지,
그동안 사람을 몇 명이나 놓치는지.

### 답할 수 없는 질문 하나를 먼저 버린다

"CCTV 환경에서 늘 잘 인식하는가"는 **판정이 불가능한 질문이다.** 사람이 멀거나,
하반신이 테이블에 가려지거나, 뒤통수만 보이면 검출률이 떨어지는 것은 버그가 아니라
물리적 한계다. `CLAUDE.md`가 "어떤 각도에서도 동작하는 알고리즘"을 명시적으로
포기하고 "좋은 각도를 고르는 설치 기준"을 택한 이유가 이것이다.

대신 답할 수 있는 질문으로 바꾼다: **"어디서부터 깨지는가."**

| 층 | 깨지면 | 고치는 방법 |
|---|---|---|
| 1. 검출 | 화면의 사람을 YOLO가 못 잡는다 | 파인튜닝, `imgsz` 상향 (`plan.md` T11) |
| 2. 포즈 | 잡긴 했는데 앉았는지 판단할 관절이 안 나온다 | 구제 경로(의자 연결·짐 증거) |
| 3. 좌석 판정 | 재료는 다 있는데 결론이 틀렸다 | 판정 로직 |

한 층만 재는 하네스는 **어느 층이 깨졌는지 못 가린다.** 그래서 세 층을 같이 낸다.

### 각도 4개를 쓰는 이유가 바뀐다

`plan.md` T15는 angle1~4를 **설치 각도 후보**로 다뤘다. 이 문서에서는 다르게 쓴다 —
**같은 카페를 찍은 조건 4개짜리 시험지**다.

- 4개 다 못 잡는다 → **모델 문제.** T11(파인튜닝) 판단 근거
- 어떤 건 잡고 어떤 건 못 잡는다 → 모델은 되는데 조건에 민감하다
- 4개 다 잘 잡는다 → 모델은 통과. 문제는 그 뒤 판정 로직이다

돌리는 비용은 1개나 4개나 비슷하므로 4개를 다 돌린다. **각도를 고르려는 것이 아니라
모델을 세 갈래로 판정하려는 것이다.** (부산물로 T15의 근거도 같이 나온다.)

## 2. 하지 않는 것

- **좌석 판정 정확도(%)를 채점하지 않는다.** "이 자리가 실제로 점유였는가"를
  채점하려면 좌석별 정답 라벨이 필요하고 그건 T16이다. T16은 설치 각도 확정(T15)
  전에 시작하면 노동이 통째로 버려진다 (`plan.md` §4).
  이 하네스가 내는 숫자는 **사람 검출 재현율** 하나뿐이다 — "화면에 있던 사람 중
  몇 %를 잡았나". 정답이 **사진당 숫자 하나**라 좌석별 라벨 없이 구할 수 있고,
  22장이면 10분이면 채워진다. 둘을 혼동하지 말 것
- **레이아웃(`--layout`)을 쓰지 않는다.** T14(사람이 좌석 칸 그리기)가 아직 안 됐고,
  **안 쓰는 편이 목적에 맞다** — 사람이 그려준 정답을 빼고 모델만 놓고 봐야
  "모델이 제대로 보는가"의 답이 나온다
- **프레임 판단 방식을 바꾸지 않는다.** 지금의 5장 다수결(`--median-frames 2`)을
  그대로 쓴다. §7 참조
- **주석 MP4를 만들지 않는다.** 배포에서 금지된 경로다 (`CLAUDE.md` 개인정보)

## 3. 만드는 것

### A. `seatnow.py --frame-dir <폴더>` (기존 파일 수정)

판정한 틱마다 그 순간을 **사진 두 장**으로 저장한다.

```
frames/angle1/clean/t0015.0s.jpg     ← 세는 용도. 박스 없음
frames/angle1/marked/t0015.0s.jpg    ← 진단 용도. 박스·판정 그려짐
```

`--no-video`와 독립이다. 둘 다 켜면 **MP4 없이 사진만** 나온다 — 이게 기본 사용법이다.

**훅 위치**: `seatnow.py:576-587`. 지금 `writer.write(render_frame(...))` 한 줄이
있는 자리 옆에 JPG 저장 분기를 둔다. `render_frame()`은 이미 있다
(`seatnow_core.py:3230`).

**깨끗한 사진이 따로 필요한 이유** — 채점자에게 답안을 먼저 보여주면 안 되기
때문이다. 주석 사진을 주고 "다 잡았나?"라고 물으면, 사람이든 LLM이든 **이미 그려진
박스에 끌려가** "네 다 잡았네요"라고 답하기 쉽다. §5에서 규칙으로 못박는다.

**파일명은 미디어 시각**이다(`t0015.0s`). 프레임 번호가 아니라 시각이어야 JSONL의
`timestamp`와 짝이 맞고, 사람이 원본 영상에서 그 지점을 찾아볼 수 있다.

### B. `judge_frames.py` (신규)

`clean/` 폴더의 사진마다 Codex를 **한 번씩 새로** 불러 사람 수를 세게 한다.

```bash
codex exec --skip-git-repo-check -s read-only --ephemeral \
  --output-schema judge_schema.json -o judge/angle1/t0015.0s.json \
  "<프롬프트> frames/angle1/clean/t0015.0s.jpg"
```

Codex CLI에 `view_image` 툴이 **기본으로 켜져 있어**(`codex features list` →
`view_image  stable  true`) 경로만 주면 사진을 스스로 연다. 인증도 이미 되어 있다
(`codex login status` → `Logged in using ChatGPT`). API 키가 필요 없다.

**답변 형식은 `--output-schema`로 강제한다.** 산문으로 답하면 파싱이 지옥이 된다.

```json
{
  "people_total": 3,
  "people_seated": 2,
  "people_standing": 1,
  "uncertain": false,
  "note": "왼쪽 창가 인물은 뒤통수만 보임"
}
```

**사진마다 세션을 새로 여는 것이 설계의 핵심이다**(`--ephemeral`). 대화를 이어가면
Codex가 "아까 3명이었으니 이번에도 비슷하겠지"로 끌려간다. 주석 박스를 안 보여주는
것과 **정확히 같은 이유**다 — 정답 쪽이 오염되면 하네스 전체가 거짓말이 된다.

### C. `inspect_run.py` (신규)

JSONL(우리 답)과 `judge/`(Codex 답)를 합쳐 판독표를 낸다.

```
사진        | YOLO가 본 것        | 앉음판정     | 좌석결론          | 실제 | 차이
t0015.0s   | 사람3 의자7 테이블2 | 앉음2 모름1  | 점유2 모름1 무시0 |  3   |  0
t0030.0s   | 사람1 의자7 테이블2 | 앉음1        | 점유1 모름0 무시1 |  3   | -2  ⚠
```

**세 층을 한 줄에 나란히 놓는 것**이 이 표의 전부다. 어느 칸에서 숫자가 무너지는지가
곧 §1의 "어디서부터 깨지는가"의 답이다.

- `YOLO가 본 것`이 이미 틀렸다 → **1층(검출) 문제.** 파인튜닝 후보
- 검출은 맞는데 `앉음판정`이 모름 → **2층(포즈) 문제.** 구제 경로
- 둘 다 맞는데 `좌석결론`이 이상 → **3층(판정 로직) 문제**

출력 3종:

1. **판독표** (마크다운) — 위 표
2. **요약** — 사람 검출 재현율, 사유 코드 분포(`seatnow_report.REASON_GROUPS`로
   install / geometry / model / time 그룹핑), 각도별 비교
3. **진단 대상 목록** — `차이 ≠ 0`인 사진들. 3단계에서 이것만 본다

**재현율 계산에서 `uncertain=true`인 사진은 뺀다.** Codex가 자신 없다고 한 것을
분모에 넣으면 그 불확실성이 우리 점수로 둔갑한다. 대신 **몇 장이 제외됐는지를 같이
찍는다** — 제외가 많으면 그것 자체가 보고할 사실이다.

## 5. 눈가림 규칙 — 이 하네스의 신뢰성 자체

정답 역할을 하는 쪽이 우리 답을 미리 보면, 이 하네스가 내는 모든 숫자가 무의미해진다.
아래는 권장이 아니라 **규칙**이다.

1. **1단계에서 Codex에게 `clean/` 폴더만 알려준다.** `marked/`와 JSONL은 1단계가
   끝날 때까지 보여주지 않는다. `codex exec -s read-only`로 돌아 파일을 고칠 수는
   없지만 **읽을 수는 있으므로**, 프롬프트에서 경로를 명시적으로 한정한다
2. **먼저 세고, 그 다음에 우리 답을 본다.** 순서가 뒤집히면 사람이든 LLM이든
   무의식적으로 코드 편을 든다. "박스가 3개 그려져 있으니 3명이 맞겠지"가 된다.
   비용이 0인 안전장치다 — 순서만 지키면 된다
3. **22장 중 5장은 사람이 따로 센다.** Codex도 틀린다. Codex가 뒤통수만 보이는
   손님을 못 세면 우리는 "YOLO가 과탐했다"고 **정반대 결론**을 낸다. 이 5장이
   어긋나면 Codex 판독 전체를 폐기한다
4. **사진을 뽑은 사람은 그 사진의 채점자가 될 수 없다.**
   `seatnow.py`는 tick마다 판정 결과를 화면에 찍는다 —
   `[30.0s] ... poses(seated/standing/unknown)=1/1/0` 의 합이 곧 **코드가 찾은
   사람 수**다. 즉 **사진을 만드는 행위 자체가 정답 후보를 눈에 넣는다.**
   §5-3의 사람 대조는 실행을 돌린 사람이 아닌 다른 사람이 해야 한다.

> 규칙 4는 2026-09-01 첫 실행 중에 **실제로 깨져서** 추가됐다. 사진을 뽑은
> 세션이 그대로 세려다가, 이미 30개 tick의 코드 답을 화면으로 본 뒤라는 것을
> 발견했다. Codex는 사진만 보므로 영향이 없고, 사람 대조만 다른 사람에게 넘겼다.

## 6. Codex 운용 — 세기와 진단을 가른다

같은 도구지만 두 작업의 요구가 정반대다.

| | 1단계 세기 | 3단계 진단 |
|---|---|---|
| 기억 | **없어야 한다** (오염 방지) | **있어야 한다** (사진 간 패턴) |
| 방식 | `codex exec --ephemeral`, 사진당 1회 | 인터랙티브 `codex`, Orca 2번 터미널 |
| 입력 | `clean/` 사진 1장 | `marked/` 사진 여러 장 + 우리 판정 |
| 출력 | JSON (스키마 강제) | 대화 |
| 자동화 | **전부 자동** (`judge_frames.py`) | 사람이 대화 |

**3단계를 TUI로 하는 이유**: "angle2는 계속 왼쪽 벽이 안 보인다" 같은 결론은 사진
여러 장을 이어봐야 나온다. 반대로 **1단계를 TUI로 하면 안 되는 이유**는 기억 오염에
더해 하나 더 있다 — Orca `terminal read`는 TUI 화면이 다시 그려지는 것을 조각으로
쌓아 돌려주므로(Orca 자체 경고) 답을 긁어내는 것이 지저분하고 깨지기 쉽다.

## 7. 프레임 판단 방식은 이번에 안 건드린다

지금 코드는 이미 여러 프레임으로 다수결을 한다. 기본값 `--median-frames 2`는 틱
시각 **앞뒤 ±2프레임(총 5장, 0.17초)**을 돌려 좌석마다 상태를 다수결로 정한다
(`seatnow.py:490-520`, `seatnow_core.py:3028` `read_burst`). 상태가 점유/빈자리/모름
이라 "중앙값"의 이산 버전이 다수결이다.

**이번 작업에서는 이 값을 그대로 둔다.** 하네스의 목적은 지금 코드가 무엇을 하는지
보는 것이지, 동시에 코드를 바꾸는 것이 아니다. 둘을 같이 하면 무엇 때문에 숫자가
달라졌는지 못 가린다.

**다만 T8(RTSP 라이브)에서는 반드시 바꿔야 한다.** 앞뒤 창은 틱 시각보다 **미래
프레임**을 봐야 하는데 라이브 스트림에는 미래가 없다. 그때 뒤쪽 창(`-9 ~ 0`)으로
바꾸며, 창 모양은 `read_burst()` 한 곳에만 있어 변경이 국소적이다. 장수를 5→10으로
늘리는 것은 틱당 추론이 **약 2배**가 되므로 T6(엣지 실측) 이후에 판단한다.

> 이 문단은 T8을 하는 사람이 이 결정을 다시 발견하지 않도록 남긴다.

## 8. 오류 처리

| 상황 | 처리 |
|---|---|
| 영상 중간에 디코딩 실패 | 지금 동작 유지 — 루프 중단, JSONL은 거기까지 유효. **부분 결과로 표를 낸다** |
| `--frame-dir` 폴더에 이미 파일이 있다 | 덮어쓴다. 파일명이 시각이라 같은 실행은 같은 이름을 낸다 |
| JPG 저장 실패(디스크 등) | **즉시 예외.** 조용히 빠뜨리면 "그 틱은 판정을 안 했다"와 구별이 안 된다 |
| Codex 호출 실패·타임아웃 | 그 사진은 `error`로 기록하고 **다음 사진으로 계속.** 22장 중 1장 때문에 전체를 버리지 않는다. 표에는 `실패`로 찍고 재현율 분모에서 뺀다 |
| Codex가 스키마를 안 지킴 | `--output-schema`가 막지만, 그래도 깨지면 `error` 취급 (위와 같음) |
| `judge/`가 비어 있다 | `inspect_run.py`는 **`실제` 칸을 비운 채로 표를 낸다.** Codex 없이 사람이 손으로 채워도 되는 형태를 유지한다 |

`seatnow_report.py`의 원칙("실패는 버그지 운영 조건이 아니다")은 판정 로직에
해당한다. 하네스는 **오프라인 조사 도구**이므로 Codex 호출 실패처럼 바깥에서 오는
실패에는 관대해야 한다. 위 표가 그 경계다.

## 9. 테스트

기존 `tests/`의 방식을 따른다 — 모델을 부르지 않고 가짜 데이터로 순수 함수를 검사한다.

**`test_frame_dir.py`** (A)
- `--frame-dir`가 틱마다 `clean/`과 `marked/`에 각각 1장씩 쓴다
- 파일명이 미디어 시각을 담고 JSONL `timestamp`와 짝이 맞는다
- `--no-video`와 같이 써도 동작하고 MP4는 안 생긴다
- 저장 실패가 조용히 넘어가지 않고 예외가 된다

**`test_judge_frames.py`** (B)
- 명령 조립: `--ephemeral`·`-s read-only`·`--output-schema`가 들어간다
  (`test_hwaccel.py`가 ffmpeg 명령을 검사하는 방식과 동일)
- 프롬프트 경로가 `clean/`으로 한정된다 — **눈가림 규칙 §5-1의 회귀 방지**
- Codex 호출 실패 시 그 사진만 `error`가 되고 루프가 계속된다
- 스키마를 벗어난 응답이 `error`로 떨어진다

**`test_inspect_run.py`** (C)
- 세 층이 한 줄에 정렬된다
- `uncertain=true`와 `error`가 재현율 분모에서 빠지고, **제외 장수가 보고된다**
- `judge/`가 비어도 `실제` 칸이 빈 표가 나온다
- 사유 코드가 `REASON_GROUPS`대로 묶인다
