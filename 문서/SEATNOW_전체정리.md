## 1. 무슨 서비스인가

카페 천장에 카메라 1대를 달고, 매장 안의 작은 컴퓨터가 15초마다 "어느 자리가
사용중인가"를 판단해서 손님 앱에 빈자리를 보여준다.

- **영상은 매장 밖으로 나가지 않는다.** 나가는 것은 "자리 이름 + 사용중/빈자리" 한 줄이다.
- 매장이 하는 일은 **설치 당일 좌석 확인 한 번**이 전부다. 그 뒤 사람 손이 필요 없다.
- 첫 설치 매장은 **문큐**(서울대 학생회관 63동 437호). 앱의 카페 id 는 `moonq` 다.

참고 논문은 Seatify (IEEE ICARC 2026, DOI 10.1109/ICARC68737.2026.11453649) — 스리랑카
대학 졸업작품이고 상업 제품이 아니라 방법론을 자유롭게 구현할 수 있다. 앉음 판정의
각도 테스트 두 개를 거기서 가져왔고, 세 번째 테스트는 일부러 뺐다 (§4-2).

## 2. 하지 않기로 한 것 — 결정 기록

같은 논의를 반복하지 않기 위해 근거와 함께 남긴다. 운영 전제로 굳은 것은 `CLAUDE.md` 에 있다.

### 카메라 2대 — ❌ 1대로 간다

매장당 1대를 전제로 설계한다. 2대를 전제한 기능(뷰 간 좌석 맞추기, 여러 영상 맞물리기)은
만들지 않는다. 좌석 배치를 1대로 못 덮으면 **좌석을 포기하거나 카메라 위치를 다시 고른다.**

이 전제의 대가: **가림이 상시적이다.** 앉은 손님의 하반신은 테이블에 가려 각도를 못 재는
것이 기본값이다. 그래서 의자 연결·짐 증거·45초 규칙 같은 구제 경로가 부가 기능이 아니라
**주 경로**다. 2026-07-18 에 의자 연결이 통째로 빠진 채 한 달 넘게 남아 있었고, 그게
치명적이었던 이유가 이것이다 (§8).

재검토 조건: 라벨링된 평가셋에서 포기 좌석 비율이 감당 못 할 수준일 때만.

### 카메라 설치를 매장에 맡기기 — ❌ 우리가 고르고 우리가 단다

기종·위치·각도·높이 전부 우리가 정하고 직접 단다. 그래서 **화각이 못 보는 좌석은
제품의 한계가 아니라 설치 결함**이고, 코드로 보정하지 않고 카메라를 다시 단다.
반대로 "보이는데 판정 실패"는 코드로 푼다. **이 둘을 섞지 않는 것**이 모름 사유 체계의
출발점이다 (§6).

### 매장별·각도별 임계값 튜닝 — ❌ 설계에서 금지

매장에 요구할 수 있는 수작업은 설치 당일 검수 한 번이 전부다. 기본값 하나로 굴러가야
한다 (`AnalyzerConfig`, `engine/seatnow_core.py:169`). 운영 중 주기적인 재확인을 전제한
설계도 만들지 않는다.

### 바 자리를 "증거 덩어리 개수"로 세기 — ❌ 사람이 칸을 긋는다

두 명이 붙어 앉으면 한 덩어리로 보여 한 명으로 세고, 그러면 빈자리를 부풀려 "자리 있음"을
잘못 내보낸다. 대신 설치 때 사람이 칸을 긋고, 한 사람이 칸 두 개에 걸치면 모름으로 낸다.
자동 등분은 원근 때문에 안 된다 (멀리 있는 칸이 좁게 보인다).

### POS기(결제 단말)에 설치 — ❌ 파일럿에서 제외

"매장 기존 PC에 설치"에서 **기존 PC ≠ POS기**로 구분한다.

1. POS는 매장 매출의 단일 장애점이다. 결제가 밀리는 사고가 한 번만 나도 그 매장을 잃는다
2. POS PC 사양이 대체로 우리 작업량보다 낮다 (저가 CPU, 메모리 4GB)
3. POS 업체가 임의 설치를 금지하고 보증을 무효화하며, 원격 업데이트로 우리 프로그램을 죽일 수 있다
4. 결제 단말과 영상 처리를 묶으면 사고 때 파장이 커진다
5. 랜포트가 없고, 운영체제가 제각각이라 섭외가 더 어려워진다

더 나은 대안: 매장에 POS 아닌 다른 PC가 있으면 그쪽이 훨씬 안전하다. 지금은 **우리가
가져가는 엣지 박스**로 정리됐다 (§7).

### 판정 결과를 2상태로 반올림하기 — ❌ 3상태를 그대로 낸다

애매한 것을 빈자리로 반올림하지 않는다. 빈자리 수는 **확신하는 것만** 센다.
모름 비율을 줄이는 것을 개발의 방향으로 삼는다 (§6).

### 바닥 좌표(발 위치)로 판정하기 — ❌ 폐기

발이 테이블에 가려 안 보이는 것이 기본값이라 쓸 수 없었다.

### 추론 입력 크기 올리기 — ❌ 정확도가 오히려 떨어졌다 (2026-09-02 실측)

긴 변을 1280보다 키우면 느려지면서 점수도 나빠졌다. 작은 짐을 건지는 일은 입력 크기
대신 **테이블마다 잘라서 한 번 더 보는 방식**으로 해결했다.

### OpenVINO 모델을 크기 고정으로 뽑기 — ❌ 금지 (2026-09-03)

크기를 박아둔 모델은 우리가 준 입력 크기를 **무시하고 자기 크기로 답한다.** 오류도 경고도
없이 빨라지기만 한다. 그래서 속도만 보고 합격을 선언하지 않는다 (§9).

### 운영 중 주기적 재캘리브레이션 — ❌ 안 한다

좌석 네모는 가구가 조금 움직이면 **스스로 따라간다** (§5-4). 카메라가 움직였을 때만 다시 그린다.

## 3. 전체 흐름 — 무엇이 어디로 가나

```
 [카페 안]                                              [서버]           [손님]
 카메라 ──영상(끊임없이)──▶ 엣지 박스 ──자리별 사용중──▶ Supabase ──▶ 앱
 4MP H.265                 15초마다 판정 한 번          한 줄 덮어씀      색칠
                                │
                                ├─ 판정 기록 (박스 디스크, 14일 뒤 삭제)
                                └─ 개선용 수치 기록 ──하루 한 번 밤에──▶ Supabase

 나가지 않는 것: 영상, 사진, 화면 좌표, 얼굴.
```

판정 한 번의 안쪽:

```
카메라 영상
  │  최신 5장을 꺼낸다 (연속 프레임)
  ▼
5장을 각각 판정 (§4)  →  자리마다 5표 다수결 (§5-1)
  ▼
확정 트래커 (§5-2)  →  앉음 2번 / 떠남 3번 / 45초 가림 규칙
  ▼
앱용 한 줄  +  판정 기록 한 줄
```

## 4. 판정 로직 ① — 사진 한 장 안에서

`SeatNowAnalyzer.analyze()` (`engine/seatnow_core.py:1428`). 사진 한 장 → 자리마다 관측 하나.

### 4-1. 전제: 자리는 사람이 그린다

설치 당일 `install/calibrate.py` 로 카메라 화면 위에 자리마다 네모를 그린다. 이게 좌석
파일(`layouts/<카페>.json`)이고 **판정의 정답 틀**이다. 모델이 테이블을 찾는 게 아니라,
**사람이 그린 네모 안에 근거가 있나**를 본다.

- 네모 종류는 둘. **테이블**은 네모 하나가 판정 단위. **바/일자형 책상**은 구역 하나에
  칸을 여러 개 그려 칸마다 판정한다.
- 의자도 그려서 어느 테이블 것인지 잇는다. **의자↔테이블 연결은 사람이 그린 묶음에서
  온다** — 상자 모양으로 추측하지 않는다.
- 네모 **밖**의 탐지는 완전히 무시한다.
- 자동 초안을 먼저 깔고 사람이 고친다. 백지에서 그리게 하지 않는다. 일자형 책상·벽에
  붙은 책상은 모델이 절대 못 잡으므로 그것만 사람이 그린다.

### 4-2. 모델 두 개를 돌린다

| 모델 | 무엇을 찾나 | 입력 크기 |
|---|---|---|
| 물체 탐지 (YOLOv8n) | 사람, 의자, 짐(노트북·컵·가방…) | 긴 변 1280 |
| 자세 추정 (YOLOv8n-pose) | 사람의 관절 17점 → 앉음/서있음/모름 | 긴 변 960 |

테이블 주변만 잘라서 물체 탐지를 한 번 더 돌린다 (최대 4곳, 긴 변 960). 먼 자리의 작은
짐이 여기서 걸린다.

**앉음 판정** (`classify_pose`). 두 각도 중 하나라도 110° 미만이면 앉음.

- 엉덩이–무릎–발목 각도
- 어깨–엉덩이–무릎 각도

논문의 세 번째 테스트(엉덩이와 무릎의 수직 거리)는 **일부러 뺐다** — 서서 몸을 굽히는
동작에서 앉음으로 잘못 잡혔다.

안전장치 셋:

- **상반신만 보이는 납작한 상자는 무조건 모름.** 카운터 뒤 직원이 앉은 것으로 잡히던
  실제 실패 사례에서 왔다.
- **움직이는 사람은 근거에서 뺀다.** 직전 판정 대비 많이 움직였으면 약한 앉음을 서있음으로
  내린다. 단 "이 규칙이 스스로 만든 서있음"은 다음 판정의 앉음 근거를 막지 못한다
  (한 번 걸으면 영원히 서있음으로 굳던 버그를 고친 것).
- 모름인 사람이 의자 네모에 충분히 겹치면 앉음으로 구제한다.

### 4-3. 근거를 자리에 잇는다

| 글자 | 근거 | 뜻 |
|---|---|---|
| `s` | 사람이 앉아 있다 | 가장 확실 |
| `t` | 책상 위에 짐이 있다 | 잠깐 자리 비운 손님 |
| `c` | 이어진 의자에 짐이 있다 | 위와 같음 |

- **들고 지나가는 짐은 뺀다.** 앉지 않은 사람의 상자와 60% 이상 겹치는 물체는 근거가
  아니다. 사람 몸 위에 뜬 헛것(바나나 오탐 등)도 여기서 걸린다.
- **한 물건은 가장 많이 덮는 자리 하나에만** 배정한다. 여러 자리에 나눠 세면 빈자리가
  줄어든다.
- 짐이 될 수 없는 것은 목록으로 뺀다: 가구(의자·소파·식탁·벤치·침대), 고정 설비(TV·냉장고·
  싱크대·오븐·전자레인지·토스터·변기·시계·화분), 동물 전체, 실외 오탐(자동차·버스·트럭·
  신호등·정지 표지).

### 4-4. 최종 규칙

```
테이블:  사람 앉음 or 책상 짐 or 의자 짐           → 사용중
         근거 없음, 그런데 모름인 사람이 옆에 있거나
         사람이 자리를 절반 이상 가림               → 모름
         근거 없음                                 → 빈자리

바 칸:   사람이 앉아 있어야만                       → 사용중
         짐만 있으면                               → 빈자리 (사유 `belongings_only`)
         한 사람이 두 칸에 걸치면 두 칸 다          → 모름
```

**바 칸에서 짐을 세지 않는 이유.** 한 손님이 카운터에 노트북·컵·가방을 펼치면 칸 두세 개가
다 사용중이 되어 "바 만석"이 뜬다. 자리를 비켜 달라면 대개 비켜 주므로 실제로는 앉을 수
있는 자리다. 테이블은 하나가 한 단위라 이 문제가 없다. (2026-09-02 재확인, 유지)

**서있는 사람은 점유 근거가 아니다** — 의도된 설계다. 다만 45초 넘게 자리를 가리고 있으면
시간 규칙이 잡는다 (§5-3).

## 5. 판정 로직 ② — 시간 축

사진 한 장의 판정은 흔들린다. 세 겹으로 안정시킨다.

### 5-1. 5장 다수결

판정 시각의 최신 5장을 각각 판정하고 자리마다 투표한다.

- 가운데 장이 출력의 기준(네모·이름)이고, 나머지 네 장은 표만 던진다.
- 사용중 대 빈자리로 과반이 나오면 그쪽, 동률이거나 과반이 없으면 가운데 장 그대로.
- 가운데 장이 포기 상태면 투표를 무시한다.
- 갈린 투표는 개선용 기록에 남는다 — 어려웠던 순간을 모으는 신호다.

목적: 한 장의 깜빡임(손이 컵을 가림, 자세 한 번 실패)이 상태를 흔들지 않게 하는 것.

### 5-2. 비대칭 확정

자리마다 "안정 상태"를 들고 있다가:

```
빈자리 ──(근거 보임)──▶ 모름 ──(15초 뒤 또 근거)──▶ 사용중
                        └──(15초 뒤 근거 없음)──▶ 빈자리

사용중 ──(근거 없음 3번 연속)──▶ 빈자리   ← 기다리는 동안 사용중을 유지
```

- **앉음 2번 / 떠남 3번 연속.** 비대칭인 이유: 빈자리를 성급히 사용중이라 하면 손님이
  불편할 뿐이지만, **사용중을 성급히 빈자리라 하면 손님이 남의 자리로 간다.**
- **확정 전 중간 상태는 모름이다.** 빈자리였던 자리에 근거가 처음 보이면 그 즉시 빈자리에서
  뺀다. 방금 앉은 자리를 15초 동안 "비었다"고 안내하지 않기 위해서다.
- **모름은 쌓아둔 횟수를 지우지 않고 멈추기만 한다.** 사람이 지나가서 잠깐 안 보인 것
  때문에 처음부터 다시 세지 않는다.
- 탐지가 3판정까지 사라져도 자리를 유지하고 위치를 예측한다. 잠깐의 가림이 자리를 없애지 않게.
- 화면이 통째로 달라지면(카메라가 돌아감) 쌓아둔 상태를 버리고 처음부터 센다.

### 5-3. 45초 가림 규칙 (2026-09-14 결정)

앉은 손님은 하반신이 테이블에 가려 "앉음"이 **끝내 안 잡힐 수 있다.** 그동안 앱에는
마지막 확정값(빈자리)이 무한정 나갔다. 손님을 남의 자리로 보내는 방향이라 시간 규칙으로 막았다.

- 자리 위의 **사람 때문에** 모름이 **3판정 연속(45초)** 이면 사용중으로 확정한다.
- 그렇게 올라간 사용중은 **비어 보이는 판정 한 번(15초)** 이면 바로 빈자리로 돌아온다.
  실제 근거로 올린 사용중이 아니므로 3번을 기다리지 않는다.
- 짐이나 화각 문제로 난 모름은 세지 않는다. "자리 위에 사람이 있다"는 뜻의 사유만 센다.
- 기록에 `occluded_streak_occupied:<연속횟수>:<원래 사유>` 이름표가 붙는다. 이 판정만 골라
  모아 사람이 정답을 매기면 **파인튜닝 재료**가 된다.

**단점을 숨기지 않는다.** 카운터 옆처럼 사람이 서서 기다리는 자리는 비었는데도 사용중이 될
수 있다. 그 방향은 손님을 남의 자리로 보내지는 않으므로 감수한다. 시험 영상 72칸에서
이 규칙으로 점수가 70/2 에서 68/4 로 내려갔고, 새 오답 2칸은 자리 옆에 서성이던 사람이
규칙대로 사용중이 된 것이다. **점수를 올리려고 이 규칙을 되돌리지 않는다.**

### 5-4. 좌석 네모가 가구를 따라간다

운영 중 가구가 조금 움직여도 네모가 천천히 미끄러진다 (`LayoutZoneTracker`).

- 네모와 30% 이상 겹치는 탐지 쪽으로 조금씩 이동한다.
- 탐지가 없는 네모(모델이 못 보는 일자형 책상)는 **마지막 위치에 고정**된다.
- 한 탐지가 두 네모와 비슷하게 겹치면 **아무 네모도 움직이지 않는다** — 잘못 따라가는 것이
  안 움직이는 것보다 나쁘다.
- 다수결의 곁가지 장들에서는 이동을 반영하지 않는다 (한 판정에 5번 곱해지는 것 방지).

### 5-5. 판단 주기는 15초 하나뿐

점유 근거가 보였을 때 5초로 당기던 2차 판단은 **뺐다** (2026-09-02). 엣지 박스에서 쓸
계산량을 예측 가능하게 두는 것이 우선이다. 같은 영상에서 12판정 → 6판정이 됐다.

## 6. 3상태와 모름 사유

판정은 `occupied`(사용중) / `empty`(빈자리) / `unknown`(모름) 세 값으로 정직하게 낸다.
모름에는 **왜 모르는지** 코드가 붙고, 사유별 분포가 곧 다음 개선 순서다.
사유는 **"누가 고치나"로 묶여 있다** (`engine/seatnow_report.py`).

| 묶음 | 사유 코드 | 고치는 방법 |
|---|---|---|
| 설치 | `border_cropped` 자리가 화면 끝에 걸림, `scene_change` 화면이 통째로 바뀜 | **카메라를 다시 단다. 코드로 안 고친다** |
| 기하·가림 | `occluded_lower_body` 하반신 가림, `ambiguous_association` 누구 자리인지 애매, `spans_multiple_seats` 한 사람이 두 칸 | 구제 경로나 네모 다시 그리기 |
| 모델 | `pose_low_keypoints` 관절 부족, `table_not_detected` | 파인튜닝 |
| 시간 | `pending_confirmation` 확정 대기, `track_predicted` 잠깐 안 보임, `occluded_by_person` 사람이 덮음 | 기다리면 풀린다. 할 일 없음 |

개선 백로그는 **기하·가림과 모델** 두 묶음뿐이다. 설치는 카메라의 일이고 시간은 저절로 풀린다.

- `ignore`(카메라가 아예 못 보는 자리)는 **앱에 나가지 않는다.** 판정 문제가 아니라 설치 결함이다.
- 빈자리 수는 **확정된 빈자리만** 센다. 모름·확정 대기·아직 확정 없음은 전부 사용중 쪽으로 센다.

## 7. 숫자와 그 근거

**전부 매장 공통 기본값 하나다.** 숫자는 전부 실측에서 나왔다 — 시험 영상의 판정들을
줄세워 "진짜"와 "틀린 것" 사이의 빈 구간 가운데를 잡는 방식이다.

### 시간

| 값 | 숫자 | 근거 |
|---|---|---|
| 판단 주기 | 15초 | 엣지 계산량을 예측 가능하게. 2차 판단은 제거 (§5-5) |
| 한 판정에 보는 장 수 | 5장 (가운데 ±2) | 깜빡임 흡수 |
| 사용중 확정 | 2번 | |
| 빈자리 확정 | 3번 연속 | 비대칭 — 빈자리를 잘못 내는 쪽이 더 나쁘다 |
| 45초 가림 규칙 | 3판정 연속 / 복귀는 1판정 | §5-3 |
| 자리를 놓치지 않고 버티는 판정 수 | 3 | 잠깐의 가림 |

### 물건을 자리에 배정할 때

| 값 | 숫자 | 근거 |
|---|---|---|
| 한 물건이 자리를 덮는 최대 비율 | 0.50 | 자리를 절반 넘게 채우는 "물건"은 가구를 잘못 본 것. 진짜 짐 30% 이하 ↔ 헛것 80% 이상. **의자에도 같은 값** (2026-09-02, 전엔 0.9 였다: 진짜 의자 짐 12건 전부 44% 이하 ↔ 벤치 63%) |
| 자리에 걸쳐야 하는 최소 비율 | 0.20 | 이만큼도 안 걸친 물건은 그 자리 것이 아니다. 진짜 26% 이상 ↔ 틀린 것 13% 이하 |
| 사람이 자리를 덮어 "안 보인다"로 보는 비율 | 0.50 | 가림 55% 이상 ↔ 스쳐 지나감 38% 이하 |
| 앉음 각도 | 110° | 논문 값. 실측에서 빈 구간(115.6 ↔ 135.2) 아래에 있어 앉은 사람 하나를 서있음으로 본다는 것이 드러났지만, 앉음 표본이 1개뿐이라 **아직 옮기지 않았다** |
| 움직이는 사람으로 보는 이동량 | 0.025 | 화면 대각선 대비 |

### 사람이 그린 자리는 그린 대로 쓴다

탐지된 테이블에는 "상판만" 추정하는 보정이 있지만, **사람이 그린 네모에는 씌우지 않는다.**
키 큰 테이블의 띠가 위로 뻗어 뒤 테이블을 덮는 일이 있었다.

## 9. 속도를 바꾸는 변경은 반드시 채점과 짝짓는다

배포는 엣지 박스에서 OpenVINO 로 돈다. 판단 하나에 쓸 수 있는 시간은 **7.5초**(주기 15초의 절반)다.

- **성능 설정을 하나 바꿀 때마다 72칸 정답지로 다시 채점한다.** 합격선 `accepted=68 wrong=4`.
- **"빠른데 틀린" 변화는 조용히 지나간다.** 크기를 박아둔 OpenVINO 모델은 우리가 준 입력
  크기를 무시하고 자기 크기로 답한다 — 오류도 경고도 없이 빨라지기만 한다.
- 한 번에 여러 개를 바꾸지 않는다. 무엇이 효과였는지 모르게 된다.
- 채점이 **오답으로 세지 않는 것 둘**: 사람이 덮어서 낸 모름, 사용중↔빈자리 전이 중의 확정
  대기. 정답지는 "사람 눈에 뭐가 있나"를 적은 것이고 우리 규칙이 무엇을 내야 하는지를 적은
  게 아니다. 이걸 오답으로 세면 점수를 올리려고 확정 지연을 없애는 쪽으로 "고치게" 된다.

## 10. 장비와 배포

| 항목 | 값 |
|---|---|
| 엣지 박스 | 중고 미니PC (Dell OptiPlex 7040 Micro · i3-6100T · 메모리 4GB · Ubuntu 24.04 · 그래픽카드 없음), 약 10만원 |
| 카메라 | 하이크비전 DS-2CD1143G2-LIU · 4MP · H.265 · 2560×1440 · 20fps · PoE · 렌즈 2.8mm, 68,000원 |
| 모델 | `yolov8n` / `yolov8n-pose` 를 OpenVINO 로 변환. 정확도는 노트북과 동일 |
| 디코딩 | 하드웨어(Quick Sync). **24시간 도는 비용을 결정하는 것은 추론이 아니라 디코딩이다** |
| 실측 비용 | 디코딩 0.43코어(22%) + 판정 3.5초(23%) ≈ 45%. 소프트웨어 디코딩으로 떨어져도 0.85코어·3.7초로 합격선 안 |
| 실행 | 리눅스 사용자 서비스. 재부팅·크래시·카메라 뽑힘 뒤 자동 복귀 |
| 설정 | `deploy/seatnow.env` 한 파일. 매장별 임계값 튜닝은 없다 |

**해상도 4MP가 상한이다** (2026-09-06 박스 실측). 6MP·8MP는 하드웨어 디코딩이 살아있을
때만 되고, 꺼지면 15초 주기를 못 맞춘다. 그리고 **꺼져도 오류가 안 난다** — 조용히
소프트웨어로 떨어져 계속 돈다. 그래서 시작할 때 실제 프레임을 뽑아 확인하고, 도중에
떨어지면 크게 경고하고 모든 기록에 남긴다.

**렌즈 2.8mm 를 기본으로 한다.** 같은 모델의 4mm 는 수평 화각이 78° 라 1대로 매장을 덮기에
좁다 (2.8mm 는 98°). 5m 거리에서 덮는 폭이 8.1m 대 11.5m 다. 못 덮은 좌석은 포기가 되고,
포기는 우리 규칙에서 설치 결함이다. 매장이 좁고 길면 그때 4mm 를 검토한다.

**카메라를 살 때 RTSP(영상 끌어오기 규격) 개방 확인이 필수다.** 모델명이 `DS-2CD` 로
시작해야 IP 카메라다 (`DS-2CE` 는 아날로그라 RTSP 가 아예 없다).

## 11. 개인정보

- **실시간 추론, 영상 미저장.** 2024년 개정 예외 조항(개인정보보호법 제25조1항6호,
  시행령 제22조1항) — 통계처리 목적으로 영상을 저장하지 않으면 예외가 적용되고, 이 경우
  얼굴 모자이크가 필요 없다. **배포 시 영상 미저장이 기본값**이고, 주석 영상을 디스크에
  쓰면 이 예외가 깨진다.
- 개인 식별을 하지 않는다. 사용중/빈자리만 판단한다.
- 카페 사장님이 운영 주체다.
- 관절 좌표는 **각도만 남기고 저장하지 않는다.**
- 사진은 어떤 형태로도 서버에 올리지 않는다 (2026-09-11, 사전적정성 검토 신청서 약속).
  배치 사진은 설치 때 사람이 폰으로 찍어 메신저로 준다.
- 카메라는 매장 안에서만 읽는다 (외부 개방·DDNS 없음).
- 학습용으로 실제 영상을 쓸 때는 얼굴 익명화와 "학습 목적 활용 동의" 조항이 필수다.
- 실제 운영 전 변호사 확인을 권한다. 이 문서가 법률 자문을 대체하지 않는다.

| `layouts/` | 매장별 좌석 파일 | |
| `tests/` | 파일 34개 · 시험 **763개** | 모델 가중치 없이 돈다 |

`engine/seatnow_core.py` 한 파일 안에서 층이 아래 순서로 나뉘고, **아래층은 위층을 모른다.**

```
① 타입·설정        상태 값, 관측 자료 모양, AnalyzerConfig
② 기하 계산        상자 겹침, 상판 추정, 중심 거리
③ 판정 순수함수    앉음 판정, 근거 연결, 들고가는 짐 제외, 최종 규칙, 가려진 자리 추론
④ 사진 분석기      네모 따라가기 + analyze()  ← 모델을 잡고 있는 유일한 곳
⑤ 시간 안정화      5장 다수결, 확정 트래커, 45초 규칙, 가구 배치 변경 감지
⑥ 입출력·그리기    장면 전환 감지, 영상 읽기·쓰기, 주석 그리기, 기록 한 줄 만들기
```

**설계 원칙:** ③층은 모델도 영상도 없이 좌표만으로 시험할 수 있어야 한다. 그래서 시험
763개가 그래픽카드도 모델 가중치도 없이 돈다. 판정 로직을 고칠 때는 **실패 사례의 실제
좌표**로 회귀 시험을 추가하는 것이 이 저장소의 관례다. 그리고 `analyze()` 의 배선을
바꿨으면 `tests/test_analyze_pipeline.py` 에도 추가한다 — 헬퍼만 부르는 시험은 "호출이
사라지는" 회귀를 못 잡는다. 의자 연결이 한 달 동안 빠진 채 시험이 전부 통과한 것이 그 예다.
