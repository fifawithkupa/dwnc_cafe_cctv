# 손님 앱용 2D 좌석 배치도

> 작성: 2026-09-01
> 기준 커밋: `JINOI/main` = `8a261d4`
> 관련: `plan.md` T13·T14, `CLAUDE.md`, `docs/superpowers/specs/2026-08-27-seat-report-contract-design.md`

## 1. 무엇을 만드나

손님이 앱을 열면 **카페 배치도가 뜨고, 어느 자리가 비었는지 색으로 보인다.**
"3자리 남음"이라는 숫자만으로는 손님이 **어느 자리**로 갈지 고를 수 없다.

지금 앱으로 나가는 것은 상태뿐이고 **위치가 하나도 없다** (`seatnow_report.py:200-207`).

```json
{ "seat_id": "T001", "kind": "table", "capacity": 1,
  "state": "occupied", "reason_code": "belongings", "confidence": 0.77 }
```

그리고 레이아웃의 좌표는 전부 **카메라 화면 좌표(픽셀)**다. 화면 좌표를 그대로
그리면 원근 때문에 찌그러진 그림이 나와 지도로 쓸 수 없다.

**이 문서는 그 없는 위치 정보를 만드는 방법과, 그것을 사람이 고치는 절차를 정한다.**

## 2. 이 문서가 정하지 않는 것

- **손님 앱 자체.** 이 저장소는 영상 분석 쪽이다. 우리가 내보내는 것은
  `floorplan.json`(지도)과 `seat_report`(상태) 두 개이고, 앱이 `seat_id`로 합친다
- **실시간 전송 경로.** `plan.md` T8·T10에서 붙는다
- **미터 단위 실측.** 손님에게 필요한 것은 "창가 오른쪽"이지 "입구에서 3.2m"가 아니다
- **각도 선정.** `angle1` 하나로 진행한다 (사용자 결정)

## 3. 순서를 결정하는 원칙 하나

> **판정에 쓰이는 것은 반드시 카메라 화면에 그려야 한다.**

판정은 화면 좌표에서 일어난다. 지도에만 그린 것은 **화면 좌표가 없어 증거가 될 수
없다.** 손님에게 보여주기만 할 장식(입구 표시 등)은 지도에만 그려도 되지만,
**벽 소파처럼 짐이 올라가면 점유가 되어야 하는 것**은 카메라 화면에 상자가 있어야
한다.

그래서 **모델이 못 잡는 것 — 창가 바, 벽 소파, 누락된 의자 — 은 전부 카메라
화면 단계에서 끝낸다.** 이것이 §6 절차의 근거다.

## 4. 좌표 변환 — 바닥 접점만 편다

설치 때 화면에서 **바닥의 직사각형** 네 귀퉁이를 클릭받아 호모그래피를 구하고,
각 상자의 **아래쪽 변 중앙**(바닥에 닿는 지점)만 평면으로 투영한다.

### 상자 전체를 펴면 안 된다

호모그래피는 **하나의 평면**을 펴는 변환이다. 바닥 평면으로 맞춘 변환에 **바닥에
있지 않은 점**을 넣으면 틀린 위치가 나온다.

- **테이블 상판은 바닥에서 약 70cm 위**다. 상판 네 귀퉁이를 바닥 평면으로 펴면
  카메라 반대쪽으로 밀려나 실제보다 멀리 그려진다
- 그래서 상자당 **점 하나**(아래쪽 변 중앙)만 쓴다. 크기와 방향은 사람이 5단계에서
  정한다

### 의자가 테이블보다 정확하다

의자는 다리가 바닥에 닿아 있어 **상자 아래쪽이 곧 바닥 접점**이다. 테이블은 검출
상자가 상판이라 아래쪽 변이 실제 다리 접점보다 위에 잡힌다.

**그래서 초안은 근사이고, 사람이 고치는 단계가 선택이 아니라 필수다.**

## 5. 데이터 모델

파일을 **둘로 나눈다.** 위치는 안 변하는데 15초마다 좌표를 같이 실어 보내면
낭비다. 앱은 지도를 한 번 받아두고 상태만 갱신한다.

| 파일 | 내용 | 언제 바뀌나 | 누가 읽나 |
|---|---|---|---|
| `layouts/<이름>.json` | 화면 좌표 상자, **의자 소속**, 바닥 네 점 | 설치 때 | **CCTV 판정** |
| `floorplan.json` | 평면 위치, 지형지물 | 설치 때 | 손님 지도 |
| `seat_report` (기존) | 상태 | 15초마다 | 손님 지도 |

셋은 `seat_id`(`T001`, `BAR7-1` …)로 이어진다.

### 레이아웃 스키마 v3

현재 v2(`seatnow_layout.py:16`)에 둘을 더한다.

```json
{
  "schema_version": 3,
  "source": { "width": 1920, "height": 1080 },
  "tables": [ { "id": 1, "name": "T1", "box": [...], "chairs": [...] } ],
  "unassigned_chairs": [ { "id": 101, "box": [820, 640, 900, 760] } ],
  "floor_reference": {
    "image_points": [[610,760],[1180,720],[1410,980],[520,1040]]
  }
}
```

- **`unassigned_chairs`** — 아직 어느 테이블 것인지 안 정한 의자. §6-3c에서 그리고
  §6-5b에서 소속을 정한다
- **`floor_reference.image_points`** — 시계방향 네 점. 실측 치수를 받지 않는다
  (§2). 가로세로 비율은 사람이 편집기에서 맞춘다

**소속 없는 의자는 파이프라인이 이미 잘 다룬다.** `chair_boxes()`에는 포함되어
증거 후보로 남고, `unit_chair_assignments()`에는 안 들어가 어떤 테이블도 점유로
만들지 않는다. 그 의자에 앉은 사람은 `inferred-seat` 경로로 떨어져 자기 자리로
잡힌다 (`filter_strong_chair_links` 주석).

### `floorplan.json`

```json
{
  "schema_version": 1,
  "extent": { "width": 1000, "height": 700 },
  "seats": [
    { "seat_id": "T001", "kind": "table", "x": 240, "y": 380, "w": 90, "h": 60 },
    { "seat_id": "BAR7-1", "kind": "counted_zone", "x": 620, "y": 90, "w": 40, "h": 40 }
  ],
  "chairs": [
    { "chair_id": 101, "seat_id": "T001", "x": 210, "y": 440, "w": 30, "h": 30 }
  ],
  "landmarks": [
    { "kind": "entrance", "label": "입구", "x": 500, "y": 690 },
    { "kind": "counter", "label": "카운터", "x": 120, "y": 200, "w": 200, "h": 60 }
  ]
}
```

좌표 단위는 **그림용 임의 단위**다. `extent`가 그 그림판의 크기다.

## 6. 설치 절차

기존 절차(`docs/edge-setup.md`)에 **두 칸**이 붙는다.

```
1. 카메라 설치                       (기존)
2. 엣지 박스 설치 → check_edge.py     (기존)
3. calibrate.py — 카메라 화면에 그리기 (기존 + 확장)
4. 바닥 네 점 클릭                    ← 신규, 3단계 안에서
5. 브라우저 편집기                    ← 신규
```

### 3단계 — `calibrate.py` (카메라 화면)

| 순서 | 무엇을 | 왜 이 순서인가 |
|---|---|---|
| **3-a** | **테이블** `[t]` — 잘못 잡은 것 지우고 못 잡은 것 추가 | 판정 단위. 나머지가 여기 붙는다 |
| **3-b** | **창가 바 구역** `[z]` + **자리 칸** `[x]` | 판정 단위. 모델이 절대 못 잡는다 |
| **3-c** | **의자** `[c]` — 과탐 지우기, 누락 추가, **벽 소파를 테이블별 조각으로** | 증거. 화면 좌표가 필요하다 |
| **3-d** | **바닥 네 점** `[f]` | 3-a~c의 상자를 펴는 데 쓴다. 마지막 |

**3-c에서는 소속을 정하지 않는다.** 위치만 그리고 "누구 것인가"는 5-b에서 정한다.
그래서 **테이블을 먼저 선택하지 않아도 의자를 그릴 수 있어야 한다** (§7 변경사항).

### 5단계 — 브라우저 편집기 (평면도)

| 순서 | 무엇을 |
|---|---|
| **5-a** | 위치·크기 다듬기 (테이블·의자·바 자리) |
| **5-b** | **의자 소속 정하기** — 의자 클릭 → 테이블 클릭 |
| **5-c** | 지형지물 추가 (입구·카운터·화장실) |
| **5-d** | 미리보기로 검수 → 저장 |

브라우저인 이유는 두 가지다. **설치가 한 자리에서 끝나야 하고**(사용자 요구), 엣지
박스가 카페 와이파이로 페이지를 띄우면 노트북이든 핸드폰이든 아무거나로 고칠 수
있다. 그리고 **그 페이지가 곧 손님 화면의 원형**이라 5-d 검수가 공짜로 따라온다.

## 7. 의자 소속을 지도에서 고치는 이유

**손으로 그린 의자→테이블 연결은 판정에서 무조건 참으로 쓰인다** — 기하학적
강한연결 필터를 건너뛴다 (`seatnow_core.py:1531-1534`).

> *"손으로 그린 의자→테이블 연결은 정답이다: 기하학적 강한연결 필터 없이
> 그대로 전파한다."*

그러므로 소속이 틀리면 **엉뚱한 테이블이 "찼음"으로 손님에게 나간다.** 빈 자리를
두고 자리가 없다고 말하는 방향이고, 매장이 손님을 잃는다.

그런데 **카메라 화면에서는 이걸 눈으로 맞추기 어렵다.** 원근 때문에 뒤쪽 의자가
화면에서 위로 올라가 옆 테이블에 붙어 보인다. 자동 매칭이 틀리는 이유와 같다
(`_chair_table_score`는 화면 픽셀 거리만 본다, `seatnow_core.py:605-632`).

**원근이 펴진 2D 지도에서는 안 헷갈린다.** 그래서 소속 편집을 여기로 옮긴다.

편집기는 저장할 때 **두 파일을 같이 갱신한다.**

| 파일 | 무엇이 바뀌나 |
|---|---|
| `layouts/<이름>.json` | **의자 소속** (`tables[].chairs` ↔ `unassigned_chairs` 이동) |
| `floorplan.json` | 평면 위치·지형지물 |

**의자의 화면 좌표 상자는 안 건드린다.** 바뀌는 것은 어느 목록에 들어 있느냐뿐이고,
판정은 그 목록을 읽으므로 **지도에서 고치면 판정이 따라온다.**

### `calibrate.py`에 없는 기능

지금은 **이미 있는 의자를 다른 테이블로 옮기는 방법이 없다.** `add_chair`는 선택된
테이블에 새로 붙이기만 한다. 지우고 다시 그리는 수밖에 없어, 의자 18개에 자동
매칭이 엉킨 상태에서는 감당이 안 된다. 이 문서가 그 구멍을 5-b로 메운다.

## 8. 가구가 움직일 때

**지도는 설치 때 그린 채로 고정한다.** 코드가 지도를 몰래 바꾸면 나중에 왜 이렇게
됐는지 추적이 안 된다.

| | 지도 | 조치 |
|---|---|---|
| **테이블** | 안 바꿈 | 과하게 움직이면 **정비 신호**를 리포트에 싣는다 |
| **의자** | 안 바꿈 | 조용히 **증거에서 제외**. 리포트에 표시하지 않는다 |

`LayoutZoneTracker`가 이미 캘리브레이션 당시 위치(`_calibrated_tables`,
`_calibrated_chairs`)를 원본 그대로 들고 있다 (`seatnow_core.py:1124-1142`).
**"처음 그린 데서 얼마나 움직였나"는 계산 가능한데 아무도 안 물어보고 있을 뿐이다.**

### 옮겨진 의자를 증거에서 빼는 이유

**의자가 옮겨졌다는 것은 다른 테이블에서 쓰고 있다는 뜻이다** (사용자 판단).
그러면 그 의자 위의 짐은 원래 테이블의 증거가 아니다. 계속 쓰면 **빈 테이블이
"찼음"으로 나간다.**

빠지는 대신 잃는 것은 구제 경로 하나뿐이고, 그 경우도 이미 처리 경로가 있다 —
연결이 끊긴 의자에 앉은 사람은 `inferred-seat`로 떨어져 자기 자리로 잡힌다.

> 2026-09-01 실측에서 `occupied_chair`(의자 위 짐으로 점유)는 판정 128건 중
> **2건(1.6%)**이었다. 다만 **손님 2명이 나오는 짧은 영상 30틱에서 나온 숫자라
> 근거가 약하다.** 붐비는 시간대에는 훨씬 많을 수 있다. 이 결정은 그 숫자가
> 아니라 위 논리에 기댄다.

### "많이 움직였다"의 자

매장마다 다른 값을 요구하면 `CLAUDE.md` 금지 사항에 걸린다. 절대 픽셀이 아니라
**그 가구 자신의 대각선 길이 대비**로 잰다. 손님이 의자를 30cm 빼는 것은 걸리지
않는다.

### 정비 신호

이 저장소에는 DB가 없다. 실제 전송은 T8·T10에서 붙으므로, 지금은 `seat_report`에
실어 내보내는 데까지 한다.

```json
"maintenance": {
  "tables_moved": ["T003"],
  "since_calibrated_at": "2026-09-01T14:20:00Z"
}
```

`tables_moved`가 비어 있지 않으면 **사람이 가서 봐야 할 매장**이다. 테이블은 잘
안 움직이므로, 뜨면 실제로 뭔가 바뀐 것이다.

## 9. 손님 화면에 보이는 것

| 색 | 뜻 |
|---|---|
| 초록 | 빈 자리 |
| 빨강 | 사용 중 |
| **회색** | **확인 안 됨** — 가려서 못 보는 자리 |

`CLAUDE.md`대로 애매한 것을 `empty`로 반올림하지 않는다. **회색을 줄이는 것이
개발의 방향**이고, 회색이 많은 구역은 우리가 카메라를 다시 달아야 한다는 신호다.
범례에 "회색은 가려서 확인이 안 되는 자리"라고 적는다.

### 의자는 크기 정보이지 상태가 아니다

판정 단위는 **테이블**과 **바 자리 칸**뿐이다. 의자는 증거이지 판정 대상이 아니다.

| | 색 |
|---|---|
| 테이블과 그 주위 의자들 | **통째로** 한 색 (테이블 단위 판정) |
| 바 자리 칸 | **칸마다** 따로 |

**4인석에 한 명만 앉아 있어도 그 테이블은 통째로 빨강이다.** 카페에서는 모르는
사람 테이블에 합석하지 않으므로 이게 맞고, **손님에게 유리한 방향의 오차**다
("자리 있다"고 했는데 없는 것이 아니라 그 반대). 범례에 "테이블 단위로
표시됩니다"라고 적는다.

의자를 그리는 이유는 **"저 테이블은 4인석이구나"를 보여주기 위해서**다.

## 10. 오류 처리

| 상황 | 처리 |
|---|---|
| 바닥 네 점이 없다 | 투영을 못 하므로 **초안 생성을 거부하고 무엇이 없는지 말한다.** 조용히 빈 지도를 내지 않는다 |
| 네 점이 직선에 가깝다(퇴화) | 호모그래피가 불안정하다. **거부하고 다시 찍게 한다** |
| 투영이 발산한다 | `extent`는 정상 투영점들의 경계상자로 정하므로 보통은 아무것도 밖으로 안 나간다. 문제가 되는 것은 **바닥 평면 뒤쪽으로 투영되어 좌표가 발산하는 점**(동차좌표의 w가 0에 가까움)이다. 그 좌석은 `extent` 가장자리에 붙이고 **`needs_review: true`**로 표시한다. 사람이 5-a에서 옮긴다 |
| `floorplan.json`에 없는 `seat_id`가 리포트에 있다 | 지도에 안 그리고 **개수를 보고한다.** 레이아웃과 지도가 어긋난 신호다 |
| 반대로 지도에만 있는 `seat_id` | 회색으로 그린다. 상태를 모르는 것과 같다 |
| 편집기 저장 중 실패 | **두 파일 중 하나만 써지면 안 된다.** 임시 파일에 쓰고 둘 다 성공하면 바꾼다 |

## 10-b. 구현은 세 단계로 나눈다

한 번에 다 만들지 않는다. **각 단계가 그것만으로 쓸모가 있어야** 중간에 멈춰도
손해가 없다.

| 단계 | 무엇 | 그것만으로 쓸모 있나 |
|---|---|---|
| **1** | 스키마 v3 + `calibrate.py` 확장(소속 없는 의자, 바닥 `[f]`) | 예 — 3-a~3-d를 끝까지 할 수 있게 된다. 지금 막혀 있는 것이 풀린다 |
| **2** | 투영 + `floorplan.json` 초안 + 브라우저 편집기 | 예 — 지도가 나오고 의자 소속을 고칠 수 있다 |
| **3** | 가구 이동 신호 (`maintenance`, 옮겨진 의자 제외) | 예 — **지도와 무관하게** 단독으로 동작한다 |

3단계는 1·2단계에 의존하지 않는다. 지도가 없어도 정비 신호는 나온다.
순서를 바꿔도 되지만, **1단계가 지금 사람을 막고 있으므로 먼저 한다.**

## 11. 테스트

기존 `tests/`의 방식을 따른다 — 모델을 부르지 않고 순수 함수를 검사한다.

**`test_floor_projection.py`**
- 알려진 직사각형 네 점으로 만든 호모그래피가 그 사각형을 정사각형으로 편다
- 상자의 아래쪽 변 중앙이 투영점으로 쓰인다 (상자 중심이 아니다)
- 퇴화한 네 점(직선에 가까움)이 거부된다
- 네 점이 없으면 초안 생성이 거부된다

**`test_layout_schema_v3.py`**
- v3가 `unassigned_chairs`와 `floor_reference`를 싣고 다시 읽힌다
- **v1·v2 파일이 그대로 읽힌다** (`unassigned_chairs`는 빈 목록으로)
- `chair_boxes()`가 소속 있는 의자와 없는 의자를 **모두** 포함한다
- `unit_chair_assignments()`가 **소속 있는 것만** 포함한다

**`test_calibrate_state.py`** (기존 파일에 추가)
- 테이블을 선택하지 않고 그린 의자가 `unassigned_chairs`로 들어간다
- 소속 없는 의자를 테이블에 붙이면 목록이 옮겨진다
- 바닥 네 점이 저장·복원된다

**`test_floorplan.py`**
- 초안 생성이 좌석·의자를 빠짐없이 싣는다
- 그림판 밖으로 나간 좌석이 "확인 필요"로 표시된다
- 편집 결과 저장이 **두 파일을 원자적으로** 갱신한다 (하나만 써지지 않는다)

**`test_furniture_drift.py`**
- 대각선 길이 대비 임계를 넘게 움직인 테이블이 `tables_moved`에 실린다
- 조금 움직인 것(손님이 의자를 빼는 정도)은 안 실린다
- 많이 움직인 의자가 `unit_chair_assignments()`에서 빠진다
- **그리고 리포트에는 의자 관련 항목이 실리지 않는다** (사용자 결정)

## 12. 완료 기준

1. `angle1`에서 3-a~3-d를 마치면 레이아웃에 **테이블·바 자리 칸·의자·바닥 네 점**이
   전부 들어 있다
2. 초안 평면도가 생성되고, **찌그러지지 않은 위에서 본 배치**로 보인다
3. 편집기에서 의자 소속을 바꾸면 **레이아웃 파일이 갱신되고, 다시 돌린 판정이
   달라진다** — 지도가 판정과 이어져 있음을 증명한다
4. 미리보기가 지금 판정을 초록/빨강/회색으로 칠한다
5. 레이아웃 있음/없음 판독표를 나란히 놓고 **사람이 그린 것이 무엇을 고쳤는지**
   숫자로 볼 수 있다 (`docs/inspect/`)
