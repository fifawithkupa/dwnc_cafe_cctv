# 앱 팀 할 일 — SitNow 좌석 상태를 손님 앱에 붙이기

> 대상: 손님 앱 개발자. 카페 하나 계약할 때마다 이 문서대로 한 번 한다.
> 2026-09-10 확정, 2026-09-11 갱신 (박스 코드 `a6320ef` 기준). 바뀌면 이 문서가 먼저 바뀐다.

## 한 장 요약

```
설치 당일 (SitNow)              계약 뒤 (앱 팀)                     운영 중
──────────────────              ──────────────                      ──────────
카메라 달고 좌석 네모 그림   →   배치 사진·이름표 목록 보고      →   박스: 15초마다 cafe_live 갱신
사람이 폰으로 배치 사진 찍음      피그마 그려 코드에 넣음              앱: seat_id 로 네모 찾아 색칠
                                 검사 통과하면 그 카페 켬
```

- 지도(배치도)는 **앱 팀이 피그마로 그려서 앱 코드에 넣는다.** 박스는 지도를 보내지 않는다.
- 박스가 보내는 건 **"자리마다 사용중인지 + 사용중 개수"** 뿐이다 (`cafe_live` 표 한 줄).
- 피그마 **네모 하나 = 이름표(`seat_id`) 하나.** 바 자리도 칸마다 네모 하나.

## 계약마다 SitNow 가 넘기는 것

| # | 무엇 | 어디 |
|---|---|---|
| 1 | 카페 id | `cafes.id` (앱 팀이 만든 줄. 아래 "0단계") |
| 2 | **배치 사진** — 설치 때 사람이 폰으로 찍은 매장 사진에 자리마다 `T1`, `BAR7-1` … 을 써 넣은 것 | 메신저로 직접 전달 |
| 3 | 이름표 목록 — 사진과 같은 내용을 글자로 (`seat_id`, `kind`, `zone`) | 메신저로 직접 전달. `cafe_live.seats` 에 같은 이름이 온다 |
| 4 | 이 문서 | — |

박스는 **사진을 올리지 않는다** (2026-09-11). 개인정보 사전적정성 검토 신청서에 "카메라 영상·사진은
어떤 형태로도 외부로 나가지 않는다" 고 적었기 때문이다. 배치 사진은 사람이 찍어서 준다.

이름표 규칙 (박스 좌석 파일에서 그대로 나온다):

- 테이블 하나 = 이름표 하나. 예 `T1`, `T2`.
- 바(카운터)는 **바 이름 + 하이픈 + 칸 번호**. 예 `BAR7-1`, `BAR7-2`. 이때 `kind = "bar_seat"`,
  `zone = "BAR7"` 로 온다. 테이블은 `kind = "table"`, `zone = null`.

## 할 일

### 0단계 — 카페 줄 만들기 (앱 팀)

`cafes` 표에 그 카페 줄을 넣는다. 다른 카페 넣던 방법 그대로 (id 규칙 `dh-###`/`snu-###`,
주소·위도경도·`place_id`·네이버지도 URL 필수). **id 를 SitNow 에 알려준다** — 박스 설정에
들어간다. 이 줄이 있어야 박스가 쓸 수 있다 (`cafe_live.cafe_id` 가 이 id 를 가리키고, 없으면
서버가 박스의 쓰기를 전부 거부한다).

### 1단계 — 피그마 그리기

배치 사진과 이름표 목록을 옆에 놓고 배치도를 그린다.

- 네모 개수 = 이름표 개수. 카메라가 못 보는 테이블은 없다 (설치 기준).
- 바 자리는 칸마다 네모 하나 (`BAR7-1`, `BAR7-2` …). 어떻게 보이게 할지는 앱 팀 UI 몫.
- 네모마다 이름표를 **목록에 적힌 글자 그대로** 붙인다. 대소문자·하이픈까지.

### 2단계 — 코드에 매칭 넣기

카페 하나당 파일 하나. 모양은 앱 팀 마음이지만 뜻은 이것이다:

```
카페 snu-101
  네모 1  ← seat_id "T1"
  네모 2  ← seat_id "T2"
  …
  네모 13 ← seat_id "BAR7-1"
  네모 14 ← seat_id "BAR7-2"
```

### 3단계 — 검사 (켜기 전에 꼭)

코드에 넣은 이름표 목록을 SitNow 에 보낸다 (텍스트, 한 줄에 이름표 하나. 빈 줄과 `#` 로 시작하는
줄은 무시된다). SitNow 가 박스 좌석 파일과 대조해서 이 중 하나를 돌려준다:

- `통과 — 14개, 이름 전부 일치`
- `실패` + 문제 목록. 나올 수 있는 문구:
  `T7 이(가) 앱에 없음` / `BAR7-9 이(가) 박스에 없음` / `t7 는 대소문자가 다름 — 박스는 T7` /
  `앱 목록에 T3 가 두 번 있음` / `개수 다름 — 박스 14개, 앱 13개`

**통과해야 그 카페를 앱에서 켠다.**

### 4단계 — 화면 규칙 (아래 "표" 절 참고)

## 표: `cafe_live` — 카페당 한 줄, 15초마다 바뀐다

앱이 운영 중에 읽는 건 이 표뿐이다. `schema_version = 2`.

| 열 | 뜻 | 앱이 하는 일 |
|---|---|---|
| `cafe_id` | `cafes.id` | — |
| `status` | `live` 정상 / `gap` 카메라 끊김 | `gap` 이면 지도 전체 "확인 중" |
| `updated_at` | **서버 시계**로 찍힌 마지막 갱신 | 지금보다 45초 넘게 오래됐으면 지도 전체 "확인 중" |
| `total_tables` | 이번 줄에 실린 자리 수 = `seats` 길이 | 앱 코드의 네모 개수와 같아야 한다. 다르면 로그 (아래 규칙 5) |
| `busy_tables` | **사용중으로 보여줄 개수** (`busy = true` 인 자리 수) | "사용중 N" |
| `free_tables` | **확정된 빈자리만** (`busy = false` 인 자리 수). `busy_tables + free_tables = total_tables` | "빈자리 N" |
| `occupied_tables`, `unknown_tables` | **이번 판정에서 본 것** (원본. 나중에 대시보드용). 확정 전 값이라 `busy_tables` 와 합이 안 맞을 수 있다 | 안 써도 된다 |
| `seats` | 아래 JSON | 이름표로 네모 찾아 색칠 |
| `tick_at` | 박스가 판정한 시각 (박스 시계, `2026-09-08T20:32:45+0900` 꼴, 참고용) | 안 써도 된다 |
| `box_version` | 박스 코드 버전 (git 짧은 해시) | 이상할 때 알려줄 때 같이 |
| `schema_version` | 이 줄의 모양 버전. 지금 `2` | 모르는 값이면 로그 |

`seats`:

```json
[
  {"seat_id": "T1",     "kind": "table",    "zone": null,   "busy": true,  "state": "occupied", "reason_code": null},
  {"seat_id": "T2",     "kind": "table",    "zone": null,   "busy": false, "state": "empty",    "reason_code": null},
  {"seat_id": "T3",     "kind": "table",    "zone": null,   "busy": false, "state": "unknown",  "reason_code": "pending_confirmation"},
  {"seat_id": "BAR7-1", "kind": "bar_seat", "zone": "BAR7", "busy": true,  "state": "unknown",  "reason_code": "occluded_lower_body"}
]
```

- **색칠은 `busy` 하나로 한다.** `true` → 사용중 색, `false` → 빈자리 색. 끝.
- **`busy` 는 "마지막으로 확정된 상태"다.** 박스는 15초마다 판정하고, 앉은 사람은 **2번** 사용중으로
  보여야 `true` 로, 떠난 자리는 **3번 연속** 비어야 `false` 로 바꾼다. 그 사이와
  모름(가림) 동안에는 **이전 값이 그대로** 나간다. 위의 `T3` 가 그 예 — 방금 누가 앉아
  이번 판정은 `unknown` 이지만 아직 확정 전이라 `busy` 는 `false` 다.
  손님 입장에선: 앉은 뒤 **약 15~30초** 뒤에 사용중이 되고, 떠난 뒤 **약 30~45초** 뒤에
  빈자리가 된다 (여기에 판정·전송에 드는 몇 초가 더 붙는다). 중간에 사람이 지나가서
  모름이 끼면 그만큼 더 늦어진다. 색이 깜빡이지 않는 대신 그만큼 늦다.
- **아직 한 번도 확정되지 않은 자리는 `busy = true` 다.** 박스가 막 켜졌거나 재시작한 직후
  1~2번의 판정에서 그럴 수 있다. 빈자리를 못 보여줄지언정 남의 자리로 보내진 않는다.
- `state` 는 박스가 이번 판정에서 낸 값 세 가지(`occupied`/`empty`/`unknown`). 색칠엔 쓰지 않는다.
  나중에 대시보드에서 "모름이 언제 생겼나"를 보려고 남겨 둔다.
- `reason_code` 는 `state = "unknown"` 일 때만 값이 있다. 우리 개발용. 안 보여줘도 된다.
  정해진 낱말만 온다 (`pending_confirmation` 방금 앉아 확정 대기, `occluded_lower_body` 가림,
  `occluded_by_person` 사람이 가림, `track_predicted` 잠깐 안 보임, `pose_low_keypoints`,
  `ambiguous_association`, `spans_multiple_seats`, `table_not_detected`, `border_cropped`,
  `scene_change`, 그리고 `status = gap` 일 때 `no_fresh_frames`). 낱말이 늘어날 수 있으니
  앱이 이 값으로 분기하지 않는다.
- `kind = "bar_seat"` 는 바 칸. `zone` 이 같은 칸끼리 같은 바다.
- `seats` 의 **순서에 기대지 않는다.** 반드시 `seat_id` 로 찾는다.

## 규칙 다섯 — 이것만은 꼭

1. **이름표는 계약 뒤 절대 바뀌지 않는다.** 카메라를 다시 잡아도 이름표는 그대로 잇는다.
   바뀌어야 하면 SitNow 가 먼저 알리고 사진을 다시 보낸다.
2. **모름 동안엔 이전 값을 유지한다.** `busy` 를 쓰면 저절로 그렇게 된다. `state` 로 직접
   칠하지 않는다 — `unknown` 을 빈자리로도, 사용중으로도 바꾸지 않는다.
3. **끊겼을 때는 "만석"이 아니라 "확인 중".** `status = 'gap'` 이거나 `updated_at` 이 45초
   넘게 멈추면 색칠을 멈추고 지도 전체를 "확인 중"으로. 끊긴 동안 `busy` 는 전부 `true`,
   `free_tables` 는 `0` 으로 오므로, 이 규칙이 없으면 만석처럼 보인다.
   두 경우가 다르다: 카메라가 죽으면 박스가 약 30초 뒤 `gap` 줄을 쓴다. 박스 인터넷이 죽으면
   줄이 마지막 값에서 멈추고 `updated_at` 만 오래된다 — 그래서 45초 규칙이 따로 필요하다.
4. **빈자리 수는 `free_tables` 그대로.** `total_tables - busy_tables` 와 같다. `occupied_tables`
   로 계산하지 않는다 — 그건 확정 전 값이다.
5. **개수가 다르면 로그.** 앱 코드에 없는 `seat_id` 가 오면 무시하고 로그. 코드엔 있는데
   안 오는 네모는 회색으로 두고 로그. 검사(3단계)를 통과했으면 평소엔 일어나지 않지만,
   드물게 어떤 자리가 그 판정에서 화면 가장자리에 걸려 한 번 빠질 수 있다 (`total_tables` 가
   한 칸 줄어든다). 그 자리는 회색, 다음 판정에서 돌아온다.

## 읽기 (supabase-js)

```js
// 카페 하나
const { data: live } = await supabase
  .from('cafe_live').select('*').eq('cafe_id', cafeId).single();

const stale =
  !live || live.status === 'gap' || Date.now() - new Date(live.updated_at) > 45_000;

// 색칠
const seen = new Set();
for (const seat of live.seats) {
  const box = boxesById[seat.seat_id];          // 앱 코드의 매칭
  if (!box) { console.warn('앱에 없는 자리', seat.seat_id); continue; }
  seen.add(seat.seat_id);
  box.color = stale ? GRAY : (seat.busy ? BUSY : FREE);
}
for (const id of Object.keys(boxesById)) {
  if (!seen.has(id)) { boxesById[id].color = GRAY; console.warn('이번 줄에 없는 자리', id); }
}

// 목록 화면: 박스가 달린 카페들 (줄이 없으면 박스가 없는 카페 — 지금처럼 보여준다)
const { data: liveAll } = await supabase
  .from('cafe_live')
  .select('cafe_id,status,total_tables,busy_tables,free_tables,updated_at');

// 실시간
supabase
  .channel(`cafe_live:${cafeId}`)
  .on('postgres_changes',
      { event: '*', schema: 'public', table: 'cafe_live', filter: `cafe_id=eq.${cafeId}` },
      (payload) => render(payload.new))
  .subscribe();
```

`cafe_live` 는 로그인 없이(anon) 읽을 수 있다. 쓰는 건 박스 계정뿐이고, 박스는 자기 카페 줄만 쓸 수 있다.

## 하지 말 것

- **`cafes.seats_available` 로 실시간 빈자리를 보여주지 않는다.** 그 칸은 앱 자체 `seats`
  표에서 자동 계산되는 값이라 카메라 판정과 무관하다. 실시간은 `cafe_live` 뿐이다.
- `cafe_maps` 표는 없다 (예전 자동 지도, 2026-09-10 에 지움). 지도는 앱 코드에 있다.
- `cafe_seat_sheets` 표와 `seat-sheets` 저장소도 없다 (예전 이름표 사진, 2026-09-11 에 지움).
  배치 사진은 메신저로 받은 것을 쓴다.
- `unknown` 을 빈자리로 칠하지 않는다. 손님을 남의 자리로 보낸다.
- `seatnow_` 로 시작하는 표는 SitNow 판정 개선용 기록이다. 앱은 읽지 않는다.

## 물어볼 곳

이름표가 사진과 다르거나, 개수가 안 맞거나, `cafe_live` 가 45초 넘게 안 바뀌면 SitNow 에
알린다. 그때 `cafe_id`, `updated_at`, `box_version` 을 같이 주면 박스 로그로 바로 원인을 본다.
