# 수동 좌석 레이아웃 (캘리브레이션) 설계

날짜: 2026-07-11
상태: 사용자 승인된 설계 (박스 존 확정, 폴리곤은 v2 후보)

## 목적

시작 시 테이블·의자 위치와 소속 관계를 사람이 등록하면, 그 레이아웃이 좌석 배치의
기준(ground truth)이 된다. 좌석 수가 탐지율과 무관하게 고정되어 손님 앱의
"몇 자리 남음" 표시가 안정된다. 자동 탐지는 각 존 안의 사람/물체/착석 상태를
채우는 용도로만 쓴다.

## 확정된 요구사항 (사용자 답변)

1. **수동 존 = 기준**: 레이아웃이 좌석 배치도의 원천. 탐지 박스로 존 위치를
   보정하지 않는다 (v1).
2. **입력은 클릭 캘리브레이션 도구**: 첫 프레임 + 자동 탐지 프리시드 위에서
   확정/수정. OpenCV highgui(Cocoa) 사용 가능 확인됨.
3. **존 밖 탐지는 무시**: 등록 안 된 테이블/의자는 판정·집계에서 제외.
4. **존은 축정렬 박스**: 폴리곤은 대각 앵글에서 존 겹침으로 인한 오분류가
   실제 관찰되면 `schema_version` 올려서 추가.

## 구성요소

### 1. 레이아웃 파일 `layouts/<이름>.json`

```json
{
  "schema_version": 1,
  "source": {
    "video": "sample_raw/영상.mp4",
    "frame_at_seconds": 0.0,
    "width": 1280,
    "height": 720
  },
  "tables": [
    {
      "id": 1,
      "name": "창가1",
      "box": [677.0, 261.0, 810.0, 450.0],
      "chairs": [
        {"id": 1, "box": [562.0, 277.0, 675.0, 442.0]}
      ]
    }
  ]
}
```

- 좌석 수 = 등록된 의자 수 (고정)
- `source.width/height`와 다른 해상도 입력이 오면 박스를 비율 스케일
- 테이블 `id`는 레이아웃에서 고정 → JSONL/앱 연동 시 좌석 ID 안정

### 2. 캘리브레이션 도구 `calibrate.py`

```
./venv/bin/python calibrate.py sample_raw/영상.mp4 --at 0 --output layouts/매장.json
```

- ffmpeg으로 `--at` 초의 프레임 추출, `SeatNowAnalyzer`의 탐지 1회로
  테이블/의자 후보를 미리 그려줌 (사람은 그리지 않음)
- 조작: 마우스 드래그 = 박스 그리기, 클릭 = 선택
- 키: `t` 테이블 모드 / `c` 의자 모드 (현재 선택된 테이블에 자동 연결) /
  `d` 선택 삭제 / `u` 실행취소 / `s` 저장 / `q` 종료
- 연결은 테이블 중심→의자 중심 선으로 상시 시각화
- 기존 레이아웃 파일을 열어 수정하는 `--edit layouts/매장.json`도 지원

### 3. 런타임 통합

- `SeatLayout` dataclass + `load_layout(path, frame_size)` (스케일 포함) →
  `seatnow_core.py`
- `SeatNowAnalyzer(..., layout=None)`: 레이아웃이 있으면 `analyze()`에서
  - 테이블 = 레이아웃 존 (`source="layout"`, confidence 1.0) —
    `select_table_candidates`/dedup 생략
  - 의자 = 레이아웃 의자 박스, 의자→테이블 연결 = 레이아웃 링크
    (`associate_chairs_to_tables`·강한 링크 필터 생략, 수동 링크는 항상
    점유 전파)
  - 사람·물체 탐지, `filter_carried_objects`, 물체/사람→존 연결,
    의자 착석/짐 판정, 디바운싱(`TableTracker`)은 기존 로직 그대로
  - 존 밖 테이블/의자 탐지 무시, inferred-seat 비활성
- `seatnow.py --layout layouts/매장.json`: JSONL `run.config`에 레이아웃
  경로·sha256 기록, 트랙 ID는 레이아웃 테이블 ID 사용
- 레이아웃 모드에서 `is_severely_border_cropped`/장면전환 리셋은 유지
  (장면이 바뀌면 레이아웃이 무효라는 신호이므로 IGNORE 처리 후 복귀)

## 에러 처리

- 레이아웃 파일 없음/스키마 불일치/빈 테이블 목록 → 실행 전 명확한 에러
- 의자 없는 테이블 허용 (물체/착석만으로 판정)
- 레이아웃 해상도와 입력 해상도 종횡비가 다르면 경고 후 비율 스케일

## 테스트

- 유닛: 레이아웃 로드/검증/스케일, 존 밖 탐지 무시, 수동 링크 점유 전파,
  기존 자동 모드 무회귀 (전체 54개 + 신규)

  테이블만 occupied 전환 확인
