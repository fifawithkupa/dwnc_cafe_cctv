# 엣지 박스 갱신 — 코드를 고친 뒤 박스에 반영하는 순서

**이미 돌고 있는 박스**에 바뀐 코드를 넣는 절차다.
박스를 **처음 만드는** 것은 `docs/edge-setup.md` (12단계).

한 줄 요약: **이 컴퓨터에서는 평소처럼 전부 올리고, 박스가 자기 쪽에서 필요한 것만 풀어 쓴다.**

---

## 1. 이 컴퓨터에서 — 평소와 똑같다

```bash
git add -A
git commit -m "..."
git push
```

바뀐 게 없다. 박스 정리는 저장소를 건드리지 않는다.

**올리기 전에 테스트를 여기서 돌린다.** 박스에는 pytest 가 없다 (`requirements-edge.txt`).
테스트는 원래 이 컴퓨터에서 도는 것이고, 박스의 확인 수단은 3절의 채점이다.

```bash
python -m pytest tests/ -q
```

---

## 2. 박스에서 — 매번 하는 것

```bash
ssh hugo@[박스IP]
cd ~/seatnow

git status          # 박스에서 직접 고친 게 있나 먼저 본다
git pull

sudo systemctl --user restart seatnow
journalctl --user -u seatnow -f     # 뜨는지 눈으로 확인, Ctrl+C 로 빠져나온다
```

`deploy/seatnow.env` 는 깃이 추적하지 않는다. 카메라 비밀번호가 들어 있어서다.
`git pull` 이 덮어쓰지 않으니 안심해도 된다.

---

## 3. 고친 게 멀쩡한지 — 박스에서 보는 법

**속도나 모델을 건드렸으면 반드시 한다** (`CLAUDE.md`).
빨라진 대신 손님을 남의 자리로 보내면 의미가 없다.

```bash
cd ~/seatnow
./venv/bin/python -m edge.check_edge          # 카메라·모델이 잡히나

# 72칸 정답지로 다시 채점
./venv/bin/python -m checks.score_answers results/edge_ov \
  --answers results/angle1_layout/angle_answer.md --title "엣지 박스"
```

합격선은 **`accepted=70`** · **`wrong=2`** 다. 이보다 나쁘면 되돌린다.

> **"빠른데 틀린" 변화를 조심한다.** 크기를 박아둔 OpenVINO 모델은 `--imgsz` 를
> 무시하고 자기 크기로 답한다. 오류도 경고도 없이 빨라지기만 한다.
> 그래서 **속도만 보고 합격을 선언하지 않는다.** 한 번에 하나씩 바꾼다.

---

## 4. 박스 정리 — 처음 한 번만

저장소에는 기획 문서·테스트·지난 실험 결과가 같이 있다. 박스에서는 하나도 안 쓴다.
**어느 파일이 실제로 도는 것인지 헷갈리는 게 문제**고, 판정 기록이 쌓이면 더 그렇다.

```bash
cd ~/seatnow
bash deploy/box_sparse_checkout.sh
```

| | 파일 수 |
|---|---:|
| 그냥 받으면 | 181개 |
| 정리하면 | **52개** |

한 번만 하면 된다. 그 뒤로는 `git pull` 만 치면 허용한 것만 풀린다.

### 이게 실제로 하는 일 (오해하기 쉽다)

**골라서 받는 게 아니라, 다 받고 일부만 풀어놓는다.**

| | |
|---|---|
| 폴더에 보이는 파일 | 52개 |
| `.git` 안에 받아둔 것 | 2.4MB · 전부 |
| 안 풀린 문서를 읽을 수 있나 | **읽힌다** (`git show HEAD:docs/edge-setup.md`) |

그래서 이게 해결하는 건 **헷갈림 하나뿐**이다.
받는 양을 줄이거나 내용을 감추는 효과는 **없다.**

- **용량을 줄이려는 것이면** 다른 걸 해야 한다 (`git clone --filter=blob:none --sparse`).
  다만 새로 복제할 때만 쓸 수 있고, 2.4MB 아끼자고 다시 복제하는 건 손해다 —
  설정 파일이 날아갈 위험이 더 크다.
- **내용을 못 보게 하려는 것이면** 둘 다 답이 아니다. 이력에 한 번 들어간 것은
  어떤 방식으로도 박스에서 읽힌다. 그런 건 **애초에 저장소에 넣지 않는 쪽**으로 간다
  (판정 기록을 `.gitignore` 에 넣은 게 그 방식이다).

### 남는 것과 빠지는 것

| 남는다 | 왜 |
|---|---|
| `engine/` | 판정 본체 |
| `edge/` | 카메라·전송·측정·판정 기록 |
| `checks/` | 3절 채점 |
| `install/` | 설치 당일 좌석 확인 |
| `layouts/` | 이 매장의 좌석 배치 |
| `deploy/` | 서비스 파일·설정·SQL |
| `results/angle1_layout/angle_answer.md` | 채점용 정답지. **`results/` 에서 박스가 쓰는 건 이 한 장뿐** |
| `README.md`·`CLAUDE.md` | 박스에 들어온 사람이 읽을 곳. 둘 합쳐 15KB |

빠진다: `docs/` · `tests/` · 지난 실험 결과 53개 · 기획/설치 문서 · `문큐연락/` · `.claude/`

### 확인과 되돌리기

```bash
git sparse-checkout list      # 지금 규칙
git sparse-checkout disable   # 원래대로. 전부 다시 풀린다
```

## 5. 판정 기록 켜기 — 처음 한 번만

무엇을 왜 모으는지는 `문서/판정개선_데이터설계.md`.

### (1) Supabase 에 표 만들기

대시보드 → SQL Editor 에 `deploy/supabase/telemetry.sql` 을 **통째로 붙여넣고 한 번 실행**한다.
표 둘과 접근 제한이 같이 들어간다.

> **접근 제한을 빼먹지 말 것.** 손님 앱과 같은 프로젝트를 쓰므로, 표만 나눠서는
> 부족하다. 안 하면 앱에 박힌 공개 키로 사람 위치 기록이 읽힌다.
> SQL 파일 끝에 이미 들어 있으니 통째로 실행하면 된다.

### (2) 박스 설정에 한 줄

`~/seatnow/deploy/seatnow.env` 를 열어 `SEATNOW_EXTRA` 를 채운다.

```
SEATNOW_EXTRA=--telemetry-dir /home/hugo/seatnow/results/live/telemetry --open-hours 11:00-17:30
```

**영업시간을 꼭 줘야 한다.** 문 닫은 시간이 구분돼야 장식과 손님 짐을 가를 수 있다.
**문큐는 11:00~17:30** 이다 (2026-09-11 확인). 매장마다 다르니 설치할 때 확인하고 적는다.

플래그를 안 주면 기록은 안 쌓이고, 코드 경로도 전혀 바뀌지 않는다.
**처음에는 플래그 없이 한 번 돌려 기존 동작이 그대로인지 보고**, 그다음에 켜는 게 안전하다.

```bash
sudo systemctl --user restart seatnow
```

### (3) 밤에 한 번 보내기

판정 루프는 **파일에 쌓기만** 한다. 보내는 건 따로 돈다 —
판단 하나에 쓸 수 있는 7.5초에 전송이 끼면 안 된다.

```bash
cd ~/seatnow
./venv/bin/python -m edge.telemetry_upload --dry-run   # 몇 줄 밀렸는지만
./venv/bin/python -m edge.telemetry_upload             # 어제까지 올린다
```

잘 되면 cron 에 하루 한 번 걸어둔다 (새벽 4시 예):

```bash
crontab -e
# 0 4 * * * cd /home/hugo/seatnow && ./venv/bin/python -m edge.telemetry_upload >> /home/hugo/seatnow/results/live/upload.log 2>&1
```

인터넷이 끊겨 있어도 **한 줄도 안 잃는다.** 파일에 그대로 남고 다음번에 밀린 날짜가 같이 올라간다.

## 6. 막혔을 때

| 증상 | 원인과 조치 |
|---|---|
| 정리했더니 `engine/` `edge/` 가 통째로 없다 | `set` 에 `--no-cone` 을 빼먹은 것. 스크립트에는 붙어 있고 필수 파일이 없으면 **스스로 되돌린다.** 손으로 칠 때만 생긴다 (2026-09-11 실제로 겪음) |
| 새로 만든 코드 폴더가 박스에 안 내려온다 | 허용 목록 방식이라 저절로는 안 온다. `deploy/box_sparse_checkout.sh` 의 `PATTERNS` 에 한 줄 추가. 스크립트가 **안 내려오는 폴더 목록을 찍어준다** |
| 채점하려는데 실험 결과 폴더가 없다 | `results/` 는 정답지 한 장만 내려온다. 필요하면 패턴에 한 줄 추가하거나 잠깐 `disable` |
| 박스에서 `pytest` 가 안 돈다 | 원래 없다. 테스트는 이 컴퓨터에서, 박스는 3절 채점으로 본다 |
| `git pull` 이 로컬 변경과 충돌한다 | 박스에서 직접 고친 파일이 있다. `git status` 로 확인하고 챙긴 뒤 다시 |
| 판정 기록이 `git status` 에 잡힌다 | 안 잡혀야 정상이다. `.gitignore` 가 제대로 왔는지 확인 — **커밋하면 사람 위치 기록이 깃허브로 올라간다** |

## 7. 설치 작업 중 노트북 네트워크는 건드리지 않는다

카메라에 붙으려고 **노트북 어댑터에 IP 를 추가하지 않는다.**
윈도우는 그 명령을 받으면 그 어댑터의 자동 주소 받기를 꺼버리고,
카페 와이파이가 그 자리에서 끊긴다 (2026-09-08 실제로 겪음).

다른 대역의 기기에 붙어야 하면 **박스를 거친다.**

```bash
ssh -L 로컬포트:카메라IP:80 hugo@[박스IP]
```

박스는 카메라와 같은 선에 붙어 있고 리눅스라 임시 주소를 붙여도 안전하다.
노트북에서 `ping`·`ssh` 같이 **읽기만 하는** 명령은 괜찮다.
