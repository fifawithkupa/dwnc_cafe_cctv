## 1. 무엇을 만드나

### 1-1. 한 줄 요약

카페 천장에 카메라 1대를 달고, 매장 안 박스가 **15초마다 자리별로 사용중/빈자리/모름**을 판정해서
손님 앱에 **빈자리 수와 자리별 색**으로 보여준다. 영상과 사진은 매장 밖으로 나가지 않는다.
나가는 것은 "자리 이름 + 사용중인지" 같은 글자뿐이다.
첫 설치 매장은 **문큐**(서울대 학생회관 63동 437호, 앱의 카페 id `moonq`)다.

### 1-2. 이 제품이 지켜야 하는 것 (우선순위 순)

1. **손님을 남의 자리로 보내지 않는다.** 앉은 손님 자리를 "빈자리"라고 안내하는 것이 최악의 오류다.
   그래서 애매하면 빈자리로 반올림하지 않고 "모름"으로 낸다.
2. **빈자리를 놓치는 건 두 번째로 나쁘다.** 비어 있는데 "사용중"이라고 하면 손님이 자리를 못 찾을 뿐,
   남의 자리에 가지는 않는다. 두 오류가 부딪치면 이쪽을 감수한다.
3. **사장님 손이 안 가야 한다.** 설치 날 1회 확인이 끝이다. 운영 중 다시 맞추거나 매장별로 숫자를 조정하지 않는다.
4. **영상을 남기지 않는다.** 개인정보보호법 "영상 미저장" 예외에 기대고 있다.

### 1-3. 설계 전제 — 코드로 풀지 않기로 한 것

| 전제 | 내용 | 따라오는 것 |
|---|---|---|
| 카메라는 우리가 고르고 단다 | 기종·위치·각도는 SitNow 팀이 정한다. 매장에 맡기지 않는다 | 화면이 못 보는 자리(무시)는 **설치 결함**이다. 코드로 보정하지 않고 카메라를 다시 단다 |
| 매장당 카메라 1대 | 2대로 가림을 푸는 기능은 만들지 않는다 | 하반신이 테이블에 가리는 게 **기본값**이다. 그래서 의자·짐으로 사용중을 알아내는 "우회 경로"가 주 경로다 |
| 좌석은 사람이 그린다 | 모델이 테이블을 찾지 않는다. 사람이 그린 네모 안에 근거가 있는지만 본다 | 일자형 책상·벽 책상처럼 모델이 못 잡는 가구도 문제없다 |
| 숫자는 하나로 | 판정에 쓰는 기준값은 전 매장 공통 (부록 A) | 매장마다 맞춰야 잘 되는 설계는 받지 않는다 |
| 3상태로 정직하게 | 사용중/빈자리/모름을 그대로 낸다. 모름에는 사유를 붙인다 | 모름 비율을 줄이는 것이 개발 방향이고, 사유별 분포가 다음 할 일 목록이다 |

## 3. 설치 날 — 좌석 지도 만들기

판정은 **사람이 그린 좌석 지도 위에서만** 한다. 지도에 없는 자리는 판정하지 않고, 앱에도 안 나간다.

### 3-1. 그리는 것

| 종류 | 무엇 | 판정 단위 | 이름 예 |
|---|---|---|---|
| 테이블 | 테이블 하나에 네모 하나 | 네모 하나가 한 자리 | `T1`, `T2` … |
| 바 / 일자형 책상 | 구역 하나를 그리고, 그 안에 **앉는 칸**을 여러 개 긋는다 | 칸 하나가 한 자리. 칸 개수가 곧 좌석 수 | `BAR7-1`, `BAR7-2` … |
| 의자 | 의자에 네모를 치고 어느 테이블 것인지 잇는다 | 판정 단위는 아님. 연결된 테이블의 근거가 된다 | — |

- 도구는 `install/calibrate.py`. 영상 한 장면을 띄우고 마우스로 그린다.
- **처음에는 AI가 테이블과 의자를 미리 잡아서 그려 준다** (`install/calibrate.py:334`). 사람은
  잘못 잡힌 것 지우기 + 못 잡은 것 추가하기만 한다. 일자형 책상·벽에 붙은 책상은 AI가 절대 못 잡으므로 사람이 그린다.
- 바 구역을 그려 놓고 칸을 안 그으면 **박스가 실행을 거부한다** (`engine/seatnow.py:163`).
  칸이 없으면 그 바의 자리가 어디에도 안 잡혀서, 앱에 실제보다 적은 자리가 나가기 때문이다.
- 앱 팀이 받은 이름표 목록과 좌석 지도의 이름이 같은지 `install/seat_check.py` 로 대조한다.
- 선을 다 꽂은 직후, **카메라 자리를 고르기 전에** `install/check_install.py` 로 연결을 한 번에 확인한다:
  카메라 영상이 들어오나, 판정이 7.5초 안에 끝나나, 그린 좌석이 화면 밖으로 빠지지 않았나, 서버 줄이 갱신되나.
  실패하면 무엇을 하라까지 알려 준다.

### 3-2. 운영 중 가구가 조금 움직이면

좌석 네모는 **AI가 잡은 테이블·의자가 움직인 만큼만 천천히 따라간다** (`engine/seatnow_core.py:1295`).

- 처음 잡힌 위치는 "기준점"으로만 기억하고, 그 뒤로 **움직인 거리만큼** 네모를 옮긴다.
  사람이 그린 네모와 AI가 잡은 네모는 원래 모양이 달라서, 위치를 그대로 맞추면 첫 장부터 네모가 엉뚱하게 움직인다.
- 한 번에 움직인 양의 35%씩만 반영한다. 가구를 제자리로 돌려놓으면 네모도 돌아온다.
- 어느 테이블 것인지 애매하면(두 네모와 비슷하게 겹치면) **움직이지 않는다.** 엉뚱한 테이블로 끌려가는 게 제일 나쁘다.
- AI가 못 잡는 가구(일자형 책상 등)의 네모는 영영 안 움직인다. 그대로 두면 된다.

**재캘리브레이션은 없다.** 가구 배치를 크게 바꾸면 그건 설치를 다시 하는 일이다.

## 4. 판정 ① — 사진 한 장 안에서 자리 하나 판정하기

### 4-1. 모델을 세 번 돌린다

| 무엇 | 찾는 것 | 입력 크기 |
|---|---|---|
| 물체 탐지 | 사람, 의자, 짐(노트북·컵·가방·책 …) | 긴 변 1280 |
| 자세 | 사람의 관절 17곳 → 앉음/서 있음/모름 | 긴 변 960 |
| 짐 다시 보기 | 짐이 하나도 안 잡힌 테이블 주변만 잘라서 확대해 다시 본다 (최대 4곳) | 960 |

세 번째는 작은 짐을 건지려는 것이다. 멀리 있는 테이블 위의 컵은 전체 화면에서는 너무 작다 (`engine/seatnow_core.py:1512`).

### 4-2. 사람이 앉았나 — 자세 판단

| 경우 | 판단 | 이유 |
|---|---|---|
| 엉덩이-무릎-발목 각도, 또는 어깨-엉덩이-무릎 각도 중 하나라도 **110° 미만** | 앉음 | 서 있으면 다리가 거의 펴져서 170° 가까이 나온다 |
| 각도를 잴 수 있는데 전부 110° 이상 | 서 있음 | |
| 관절이 안 보여서 각도를 못 잼 | **모름** | 하반신이 테이블에 가린 손님이 대부분 여기다. 서 있음으로 넘기지 않는다 |
| 상반신만 보이는 납작한 사람 | **모름** | 실제 카페 시험에서 카운터 뒤 직원(허리 아래가 가림)이 앉은 손님으로 잡혔다 |
| 모름인데 **그려 둔 의자 위에 충분히 겹쳐 있음** | 앉음 (구제) | 의자 위에 있으면 앉았다고 봐도 된다. 단 각도로 확인된 앉음보다 약한 근거로 친다 |
| 직전 판정에서 서 있던 사람이 이번엔 약한 근거로만 앉음 | 서 있음 | 지나가는 사람을 손님으로 치지 않으려고 |
| 같은 사람이 "서 있음"과 "약한 앉음" 두 번 잡힘 | 모름 | 각도로 확인된 서 있음을 믿는다 |

(`engine/seatnow_core.py:468` 자세 판단, `:1722-1752` 의자 구제·움직임 거르기)

### 4-3. 자리의 근거 세 가지

자리 네모 안이나 그 자리에 연결된 의자 위에 무엇이 있는지 본다.

| 글자 | 근거 | 뜻 | 확실한 정도 |
|---|---|---|---|
| `s` | 사람이 앉아 있다 (테이블 옆, 또는 연결된 의자 위) | 손님이 있다 | 가장 확실 |
| `t` | 책상 위에 짐이 있다 | 잠깐 자리를 비운 손님 | 손님이 돌아올지는 덜 확실 |
| `c` | 연결된 의자 위에 짐이 있다 | 위와 같음 | 위와 같음 |

### 4-4. 무엇을 짐으로 치고 무엇을 안 치나

짐 오인이 곧 "빈자리를 사용중이라고 하는" 오류라서 걸러내는 규칙이 여럿이다.
아래 숫자는 전부 **시험 영상에서 진짜 짐과 오인이 깔끔하게 갈린 틈**에서 정했다.

| 규칙 | 기준 | 왜 |
|---|---|---|
| 짐이 될 수 없는 종류는 뺀다 | 사람·의자·소파·테이블·화분·TV·냉장고·동물·차량·시계 등 (`:54`) | 가구와 고정물은 손님 짐이 아니다 |
| **자리보다 너무 큰 "짐"은 가구를 잘못 본 것** | 자리 면적의 50% 초과면 버린다 (`:558`) | 빈 밝은 상판이 닫힌 노트북으로 잡혀 빈 테이블이 사용중이 됐다. 실측: 진짜 짐 ≤30%, 오인 ≥80% |
| 자리에 조금만 걸친 짐은 그 자리 것이 아니다 | 짐의 20% 이상이 자리 안이어야 한다 (`:566`) | 옆자리 짐이 새어들어왔다. 실측: 맞는 배정 ≥26%, 틀린 배정 ≤13% |
| 짐 하나는 한 자리에만 | 두 자리에 걸치면 **더 많이 덮은 쪽** | 사람이 보는 기준과 같다 |
| 손에 들고 가는 물건은 뺀다 | 서 있거나 모름인 사람 몸과 60% 이상 겹치면 버린다 (`:848`) | 가방 들고 지나가는 손님 때문에 자리가 사용중이 되면 안 된다 |
| 의자 위 짐 | 짐의 55% 이상이 의자 안. 의자 면적 50% 초과는 가구 오인 | 창가 벤치가 "여행가방"으로 잡혀 빈 의자가 사용중이 됐다 |
| 테이블 짐과 의자 짐은 겹쳐 세지 않는다 | 테이블이 가져간 짐은 의자 근거에서 뺀다 | |

### 4-5. 사람이 자리를 가리면

자리 네모의 **50% 이상을 사람 한 명이 덮고 있으면** "가려서 안 보인다"로 본다 (`:996`).
이때 근거가 하나도 안 보여도 **빈자리가 아니라 모름**이다. 안 보이는 것과 없는 것은 다르다 —
짐을 두고 잠깐 일어난 손님 자리 앞에 직원이 서 있을 수 있다.
(실측: 가림으로 볼 장면은 55% 이상, 스쳐 지나가는 정도는 38% 이하였다.)

### 4-6. 최종 규칙

```
테이블 자리
  사람 앉음(s) 또는 책상 짐(t) 또는 의자 짐(c)   → 사용중
  근거 없음 + 자세 모름인 사람이 옆에 있음        → 모름  (사유: nearby_person_pose_unknown)
  근거 없음 + 사람이 자리를 50% 이상 가림         → 모름  (사유: occluded_by_person)
  근거 없음                                       → 빈자리 (사유: no_customer_evidence)

바 칸
  사람 앉음(s)                                    → 사용중
  짐만 있음                                       → 빈자리 (사유: belongings_only)
  자세 모름인 사람 / 가림                          → 모름
  사람 한 명의 몸이 두 칸 이상에 걸침              → 걸친 칸 전부 모름 (사유: spans_multiple_seats)
```

(`engine/seatnow_core.py:1012` 최종 규칙, `:1101` 바 두 칸 걸침)

**바 칸에서 짐을 안 치는 이유.** 바에서는 손님 한 명의 노트북·컵·가방이 옆 칸 두세 개에 퍼진다.
짐을 근거로 치면 손님 한 명이 세 자리를 먹는다. 테이블은 원래 한 단위라 이 문제가 없다.
대신 **"짐만 있는 바 칸"을 앱은 빈자리로 보여준다** — 손님이 가서 "치워 주실래요?"라고 해야 한다.
이 선택은 `belongings_only` 사유로 따로 세어서 얼마나 자주 일어나는지 볼 수 있다.

**바에서 한 사람이 두 칸에 걸치면 둘 다 모름인 이유.** 한 명인지 어깨를 붙이고 앉은 두 명인지 모른다.
한 칸만 사용중으로 치면 빈자리 수가 부풀어서 꽉 찬 바로 손님을 보낸다.

## 5. 판정 ② — 흔들림 거르기 (5장 다수결 → 시간 축 확정)

한 장의 판정은 흔들린다. 사람이 고개를 숙이거나, 컵이 한 장에서만 안 잡히거나, 직원이 지나간다.
세 겹으로 안정시킨다.

### 5-1. 5장 다수결 (한 판정 안에서)

판정 시각의 **가장 최근 연속 5장**(약 0.25초 분량)을 각각 판정하고 자리마다 투표한다
(`engine/seatnow_core.py:2122`).

- **사용중 표와 빈자리 표만 비교한다.** 모름 표는 세지 않는다. 많은 쪽으로 가고,
  동률이면(둘 다 0표인 경우 포함) 가운데 장의 판정을 그대로 쓴다.
  그래서 5장 중 4장이 모름이고 1장만 사용중이어도 그 판정은 사용중이 된다 — 한 장이라도 근거가 보이면 살린다.
- 이긴 쪽의 근거(어떤 짐, 몇 명)도 같이 가져와서, 기록에 남는 근거와 상태가 어긋나지 않게 한다.
- 투표가 갈린 자리는 "어려웠던 순간"으로 개선용 기록에 남는다 (9절).

### 5-2. 시간 축 확정 — 자리마다 "확정 상태"를 들고 있다

| 바뀌는 방향 | 필요한 것 | 앱에 보이기까지 | 왜 |
|---|---|---|---|
| 빈자리 → 사용중 | 사용중 판정 **2번** 누적 | 앉은 뒤 약 **15~30초** | 한 장 오인으로 빈자리를 지우지 않으려고 |
| 사용중 → 빈자리 | 빈자리 판정 **3번 연속** | 떠난 뒤 약 **30~45초** | 화장실 간 손님 자리를 지키려고 |
| 모름 판정이 들어옴 | 세던 횟수를 **지우지 않고 멈춘다** | — | 사람이 잠깐 지나가 가렸다고 처음부터 다시 세지 않는다 |

(`engine/seatnow_core.py:2664`)

### 5-3. 45초 가림 규칙 (2026-09-14 추가)

**문제.** 앉은 손님은 하반신이 테이블에 가려 자세가 "모름"으로만 나온다. 모름은 확정을 멈추기만 하므로,
그 사이 앱에는 **마지막 확정값(빈자리)이 무한정** 나갔다. 손님이 앉아 있는데 앱은 계속 빈자리라고 했다.

**규칙.** "사람 때문에 모름"이 **3판정(45초) 연속**이면 앉은 손님으로 보고 사용중으로 확정한다
(`engine/seatnow_core.py:2748`). 지나가는 사람은 45초 내내 같은 자리 위에 있지 않는다는 전제다.

- "사람 때문에 모름"에 드는 사유: 사람이 자리를 가림, 자세 모름인 사람이 옆에 있음, 바 두 칸 걸침,
  관절 부족, 상반신만 보임. 화각이나 짐 때문에 나온 모름은 세지 않는다.
- 이렇게 올라간 사용중은 실제 근거가 아니라서 **오래 붙들지 않는다.** 비어 보이는 판정이 한 번(15초)만
  나와도 바로 빈자리로 돌아간다. 3번 연속을 기다리지 않는다.
- 기록에 `occluded_streak_occupied` 이름표가 붙는다. 이 판정들만 모아 사람이 정답을 매기면
  "가려진 채 앉은 사람" 학습 재료가 된다.

**대가.** 카운터 옆처럼 **사람이 서서 기다리는 자리는 비어 있어도 사용중이 될 수 있다.**
실제로 72칸 채점에서 시험 영상의 T3(자리 옆에서 서성이는 사람) 2칸이 이 규칙 때문에 틀렸다 (7절).
이 방향은 빈자리를 놓칠 뿐 손님을 남의 자리로 보내지는 않으므로 감수했다.

### 5-4. 장면이 통째로 바뀌면

카메라가 밀리거나 화면이 갑자기 달라지면(특징점이 거의 안 맞고, 색 분포와 밝기가 크게 달라짐)
쌓아 둔 확정 상태를 **전부 버리고 처음부터 센다.** 그 판정은 전 자리 "무시"로 낸다 (`engine/seatnow.py:425`).
옛 화면 기준의 확정값을 새 화면에 이어 붙이면 엉뚱한 자리가 사용중으로 남는다.

## 6. 앱에 나가는 것

### 6-1. `cafe_live` 표 — 카페당 한 줄, 15초마다 덮어쓴다

앱이 운영 중에 읽는 건 이 줄 하나다. 표 모양과 화면 규칙의 기준 문서는 `문서/앱팀할일.md`.

| 칸 | 뜻 |
|---|---|
| 자리마다 `seat_id` · `kind` · `zone` | 자리 이름(`T1`, `BAR7-2`), 테이블/바 칸, 바 구역 이름 |
| 자리마다 **`busy`** | **앱은 이 한 칸으로 색칠한다.** 마지막으로 *확정된* 상태가 빈자리일 때만 `false` |
| 자리마다 `state` · `reason_code` | 이번 판정의 사용중/빈자리/모름과, 모름일 때 그 사유 (참고용) |
| `free_tables` / `busy_tables` | `busy` 기준 빈자리 수 / 사용중 수 |
| `status` | `live` 평소 / `gap` 카메라 화면이 끊김 |
| `updated_at` | 서버 시계로 찍힌 마지막 갱신 |

(`edge/publish.py:74` 한 줄 만들기, `:40` 개수 세기)

### 6-2. 앱 화면 규칙과 그 결과

- **앱은 확정된 값만 본다.** 모름·확정 대기 동안에는 이전에 확정된 값이 그대로 보인다. 그래서 색이 깜빡이지 않는다.
- **아직 한 번도 확정된 적 없는 자리**(박스를 막 켰을 때 모름으로 시작한 자리)는 사용중으로 보인다.
- **카메라가 15초 넘게 새 화면을 안 주면** 박스가 `status = gap` 줄을 쓴다. 전 자리 사용중 쪽(모름), 빈자리 0.
  옛 화면으로 판정하지 않는다.
- **박스 인터넷이 끊기면** 줄이 마지막 값에서 멈춘다. 앱은 `updated_at` 이 45초 넘게 오래되면 지도 전체를 "확인 중"으로 바꾼다.
- 카메라가 못 보는 자리(무시)는 앱에 아예 안 나간다.
- 지도 그림(배치도)은 앱 팀이 피그마로 그려 앱에 넣는다. 박스는 지도도 사진도 보내지 않는다.

### 6-3. 손님 눈에 보이는 시간표

| 상황 | 0초 | 15초 판정 | 30초 판정 | 45초 판정 |
|---|---|---|---|---|
| 손님이 빈 테이블에 앉음 (하반신 보임) | 앉음 | 1번째 사용중 → **앱: 빈자리 그대로** | 2번째 → **앱: 사용중** | |
| 손님이 앉았는데 하반신이 가림 | 앉음 | 모름 1 → 앱: 빈자리 그대로 | 모름 2 → 앱: 빈자리 그대로 | 모름 3 → **앱: 사용중** (45초 규칙) |
| 손님이 짐 없이 떠남 | 떠남 | 빈자리 1 → 앱: 사용중 그대로 | 빈자리 2 → 앱: 사용중 그대로 | 빈자리 3 → **앱: 빈자리** |
| 손님이 짐을 두고 화장실 | 일어남 | 짐(t) → 사용중 유지 | 사용중 유지 | 사용중 유지 |

판정은 손님이 앉은 순간이 아니라 15초 간격 정해진 시각에 돌므로, 실제 지연은 위 표보다 0~15초 짧을 수 있다.

### 6-4. 전송 방식

- 전송은 판정과 **따로 도는 일꾼(백그라운드)** 이 한다. 판정은 전송을 절대 기다리지 않는다.
- 실패한 값은 **버린다.** 다음 판정 값이 더 새롭기 때문이다. 다시 시도 간격은 5초 → 최대 60초로 늘어난다.
- 박스 계정은 **자기 카페 줄만** 쓸 수 있고(서버의 행 단위 권한), 앱은 읽기만 한다. 박스를 누가 가져가도 다른 카페 데이터는 못 건드린다.
- 앱 팀이 먼저 만든 `cafes` 표는 박스가 건드리지 않는다 (앱의 자동 계산이 덮어쓰기 때문).

## 7. 지금 얼마나 맞나 — 72칸 정답지

시험 영상(angle1, 매장 하나·각도 하나) 72칸을 사람이 손으로 채점한 정답지에 맞춰 본 결과다
(`results/angle1_layout/채점표.md`).

```
72칸 중 68칸 합격 (딱 맞음 58 + 확정 대기 3 + 가림 모름 7) · 오답 4
```

- **확정 대기**(사용중↔빈자리로 넘어가는 중이라 아직 이전 값)와 **가림 모름**(사람이 덮어서 낸 모름)은
  규칙이 일부러 낸 답이라 합격으로 센다.
- 기준선은 `합격 68 · 오답 4`. 이보다 나빠지는 변경은 되돌린다. 노트북과 박스(OpenVINO)가 같은 점수여야 한다.
- 45초 규칙 전에는 `70 · 2` 였다. 규칙을 넣으며 2칸이 새로 틀렸고, 이유를 알고 감수했다 (아래 표).

### 7-1. 틀린 4칸

| 시각 | 자리 | 정답 | 앱 | 무슨 일 | 손님에게 |
|---|---|---|---|---|---|
| 30초 | T5 | 사용중 (책상 짐) | 빈자리 | **탐지 모델이 책상 위 짐을 못 봄** | **남의 자리로 간다 — 가장 나쁜 방향** |
| 45초 | T5 | 사용중 (책상 짐) | 빈자리 | 위와 같음 | 위와 같음 |
| 45초 | T3 | 빈자리 | 사용중 | 자리 옆에 서성이던 사람이 45초 규칙에 걸림 | 빈자리를 못 찾는다 |
| 60초 | T3 | 빈자리 | 사용중 | 위와 같음 | 위와 같음 |

**T5 두 칸이 진짜 문제다.** 코드가 버린 게 아니라 모델이 애초에 짐을 못 봤다. 규칙을 고쳐서는 안 풀리고,
우리 카메라 화면으로 모델을 다시 가르쳐야(파인튜닝) 풀린다.

### 7-2. 상태는 맞았지만 근거를 놓친 것

- 의자 위 짐(`c`)을 자주 놓친다 (T6 세 칸, BAR7-6). 다른 근거(책상 짐)가 있어서 상태는 맞았다.
- 가려진 채 앉은 사람(`s`)을 못 본다 (30초 T3). 45초 규칙이 이걸 보완하려고 들어갔다.

### 7-3. 이 숫자의 한계

**평가셋이 영상 한 편, 72칸뿐이다.** 다른 매장·다른 각도·다른 조명에서 같은 점수가 나온다는 근거는 아직 없다.
첫 실매장(문큐) 설치 뒤 그 매장 정답지를 만드는 것이 이 숫자를 믿을 수 있게 만드는 유일한 방법이다.

## 9. 기록 — 판정을 계속 좋게 만들기 위한 재료

### 9-1. 박스 안 판정 기록 (매 판정)

`results/live/<날짜>.jsonl` 에 판정마다 한 줄. **14일 뒤 자동 삭제.** 박스 밖으로 나가지 않는다.

- 자리마다: 이번 장 판정 · 확정 상태 · 앱에 나간 값 · 사유 · 5장 투표 결과 · 근거 물체(이름·확신도·그 자리 안 비율)
- 판정 품질: 걸린 시간 · 늦게 시작한 정도 · 메모리 · 하드웨어 디코더 상태 · 재연결 횟수 · 전송 성공/실패
- `edge/live_report.py` 로 하루치 요약을 본다.

### 9-2. 개선용 기록 (켰을 때만, 하루 한 번 밤에 서버로)

설계 근거는 `문서/판정개선_데이터설계.md`.
**지금은 꺼져 있다.** 받을 서버 표를 아직 만들지 않아서, 켜면 전송이 전부 실패한다.
설치가 끝나고 판정이 안정된 뒤 표를 만들고 켠다 (`문서/plan.md` §3).

| 표 | 무엇을 | 얼마나 |
|---|---|---|
| 순간 기록 (`seatnow_seat_ticks`) | 자리 하나 × 판정 하나 | **고른 것만**: 앱 값이 바뀐 순간 / 어려웠던 순간(모름, 이번 장과 확정이 다름, 5장 투표가 갈림) / 편향을 막는 무작위 대조군 1% |
| 하루 요약 (`seatnow_seat_daily`) | 자리 × 날짜 | **모든 판정**을 센다. 고른 것만 세면 모름 비율이 틀어진다 |

- 위치는 전부 **"그 자리를 1로 본 비율"** 이다. 화면 좌표·사진은 나가지 않는다.
- 박스는 파일에 덧붙이기만 하고 올리는 건 밤에 따로 한다. 7.5초 판정 시간을 안 건드리려고.
- 올라간 게 확인된 파일만 지운다. 인터넷이 끊긴 날은 다음 날 같이 올라간다.
- 영업시간을 알려 주면 문 닫은 시간에 보이는 "짐"을 장식으로 가려낼 수 있다.

### 9-3. 모름 사유 — "누가 고치나"로 묶는다

판정마다 모름에는 사유가 붙는다 (`engine/seatnow_report.py`). 사유별 분포가 곧 다음 개선 순서다.

| 묶음 | 사유 | 뜻 | 고치는 방법 |
|---|---|---|---|
| 설치 | `border_cropped`, `scene_change` | 자리가 화면 끝에 걸림 / 장면이 바뀜 | **카메라를 다시 단다.** 코드로 안 고친다 |
| 기하·가림 | `occluded_lower_body` | 상반신만 보이는 사람 | 의자 연결·짐 같은 우회 경로, 네모 다시 그리기 |
| | `ambiguous_association` | 자세 모름인 사람이 옆에 있어 누구 자리인지 애매 | 위와 같음 |
| | `spans_multiple_seats` | 바에서 한 사람이 두 칸에 걸침 | 칸을 다시 긋기 |
| 모델 | `pose_low_keypoints` | 관절이 부족해 자세를 모름 | 파인튜닝 또는 더 큰 입력 |
| | `table_not_detected` | 테이블을 못 잡음 | 위와 같음 |
| 시간 | `pending_confirmation` | 사용중 근거를 처음 봐서 확정 대기 | 기다리면 풀린다 |
| | `track_predicted` | 잠깐 안 보여 이전 값으로 버팀 | 기다리면 풀린다 |
| | `occluded_by_person` | 사람이 자리를 덮어서 안 보임 | 비키면 풀린다 |
| (전송) | `no_fresh_frames` | 카메라 화면이 끊김 (앱에만 나감) | 카메라·선 점검 |

개선 대상은 **기하·가림과 모델** 두 묶음뿐이다. 설치 묶음은 카메라 문제고, 시간 묶음은 할 일이 없다.

## 11. 알려진 한계와 트레이드오프

**손님에게 틀린 정보가 가는 방향부터** 적는다.

### 11-1. 손님이 남의 자리로 갈 수 있는 경우 (가장 나쁜 방향)

| # | 경우 | 얼마나 | 지금 대응 |
|---|---|---|---|
| 1 | **앉은 직후 최대 약 30초**, 앱은 그 자리를 빈자리로 보여준다 | 손님이 앉을 때마다 | 의도된 지연. 한 장 오인으로 빈자리를 지우지 않는 대가 |
| 2 | **하반신이 가린 채 앉은 손님은 최대 약 45초** 빈자리로 보인다 | 1대 카메라에선 흔하다 | 45초 규칙이 그 이상은 막는다 |
| 3 | **모델이 작은 짐을 못 보면** 짐만 두고 비운 자리가 빈자리로 나간다 | 72칸 중 2칸 (T5) | 규칙으로는 안 풀림. 파인튜닝 필요 |
| 4 | 지갑·휴대폰처럼 모델이 이름을 모르는 물건만 두고 간 자리 | 측정 안 됨 | "빈 상태 대비 변화량" 신호를 계획 중 (12절) |
| 5 | 바 칸에 짐만 두고 간 손님 자리는 빈자리로 나간다 | 의도된 선택 | 손님이 "치워 주세요" 하면 된다는 전제. `belongings_only` 로 빈도를 잰다 |

### 11-2. 빈자리를 못 찾게 하는 경우

| # | 경우 | 지금 대응 |
|---|---|---|
| 6 | 떠난 뒤 약 30~45초 사용중으로 남는다 | 의도된 지연. 화장실 간 손님 자리를 지키는 대가 |
| 7 | 자리 옆에 45초 넘게 서 있는 사람(대기 줄·직원) 때문에 빈자리가 사용중이 된다 | 72칸 중 2칸 (T3). 비어 보이면 15초 만에 풀린다 |
| 8 | 박스를 막 켰을 때 확정 전인 자리, 카메라가 끊긴 동안은 전부 사용중(또는 "확인 중") | 의도된 선택. 모르면 빈자리라고 하지 않는다 |

### 11-3. 아직 확인 못 한 것

- **평가는 영상 한 편 72칸뿐이다.** 다른 매장에서의 정확도는 모른다 (7-3).
- **탐지·자세 모델은 공개 모델 그대로다.** 카페 화면으로 다시 가르치지 않았다. 7절의 놓침 대부분이 여기서 온다.
- **설치 합격 기준이 아직 숫자로 없다.** "못 보는 자리 비율 몇 % 이하"와 카메라 높이·각도 기준을
  정하기로 했지만(`CLAUDE.md`) 아직 정하지 않았다. 지금 좌석 지도 방식에서는 못 보는 자리를 코드가
  자동으로 "무시"로 내지 않고, **사람이 그 자리를 안 그리는 것**으로 처리된다. 그래서 설치 날 사람이 놓치면 기록에도 안 남는다.
- 판정에 쓰는 기준값(부록 A)은 전부 시험 영상 하나에서 실측으로 정했다. 매장이 늘면 다시 확인해야 한다.
